**좌표 결정 규칙** (`StaticLoadRunner.readCoords` → `SubwayGraphBuilder`)
1. 서울교통공사 역사 좌표(1~8호선 운영 역, 232개)가 있으면 그것.
2. 없으면 국가철도공단 역위치의 (노선, 역) 좌표, 없으면 이름만 같은 좌표. 0,0·수도권 밖·형식 오류는 무효로 건너뛴다.
   - **세 원천 다수결**(`StationCoordCrossCheck.majority`, S15P21A104-113): 국가철도공단 좌표가 표준데이터와 500 m 넘게 어긋나는데 표준데이터·KTDB 는 500 m 안에서 일치하면 국가철도공단 쪽 오기로 보고 표준데이터 좌표를 쓴다 — 한국항공대(4.9 km, 경의중앙 파일)·송도(2.5 km, 수인분당 파일: 연수역 자리)·산본(1.1 km, 4호선 파일). 두 원천만 비교하면 "유지, 검토 필요"에 머물던 값이다.
3. 그것도 없으면 전국도시철도역사정보표준데이터의 (노선, 역) 좌표 — 국가철도공단 역위치 파일이 없는 경춘·경강·서해·공항철도·신분당·우이신설·신림 역(다수결 대체 6개 포함 90개).
4. 2·3 의 좌표를 KTDB 노드(수도권 범위, 이름별 평균)와 대조해 **5 km 넘게 어긋나면 파일 오기로 보고 KTDB 좌표를 쓴다**. 500 m~5 km 는 유지하고 "검토 필요" 경고. 2026-09-10 기준 청산·별내별가람·청명은 다수결이 먼저 잡아 여기까지 오는 역은 0개다.
5. 그래도 없으면 KTDB 노드. KTDB 는 선로 노드 좌표라 역사 좌표와 수십 m(중앙값 29 m, 95% 140 m) 차이가 난다 — 현재 0개.
6. 어느 원천에도 없으면 null — 현재 0개.

## 시각표 파일 읽는 규칙 (`TrainTimetableParser`)

- 열: `고유번호 · 호선 · 역사코드 · 역사명 · 주중주말 · 방향 · 급행여부 · 열차코드 · 열차도착시간 · 열차출발시간 · 출발역 · 도착역`. 행 1개 = 열차 1대의 역 1개 정차.
- `호선` 1~9 → `line_id` 1001~1009. `주중주말` DAY/SAT/END → `dow_type` 0/1/2. `방향` UP/DOWN(일반)·IN/OUT(2호선)은 쓰지 않는다 — 방향은 열차의 정차 순서에서 나온다.
- 열차(호선·요일·열차코드)별로 정차를 시각순 정렬해 인접 역 쌍을 뽑는다. 첫 정차의 도착·막 정차의 출발은 비어 있다(정상).
- **구간 소요 = 다음 역 출발 − 이 역 출발** (S15P21A104-111). 도착이 아니라 출발까지 재므로 **도착역의 정차시간이 구간에 들어간다** — 정차는 호선별 중앙값 30초(9호선 25초)다. 종착역은 출발 시각이 없어 도착 시각으로 잰다.
  - 도착 기준(`다음 역 도착 − 이 역 출발`)으로 재던 값은 역마다 정차시간이 빠져 짧았다. 강변→역삼(7구간) 11분 → 15분, 역삼→합정(17구간) 28분 30초 → 38분 30초. 시각표의 실제 소요(역삼 도착 − 강변 출발)는 14분 30초·38분이다.
  - 정차를 **도착역 쪽에** 붙이는 이유: `wait_sec` 이 "열차가 출발할 때까지의 대기"라 출발역 정차는 이미 지나간 시간이다. 출발역 쪽에 붙이면 같은 정차를 두 번 센다. 대신 경로의 마지막 구간에서 목적지 정차 1회(약 30초)가 더 세어진다 — 엣지 값이 경로 위치와 무관해야 하므로 받아들인다.
- 시각은 `HH:MM:SS` 이고 자정 넘는 열차는 `24:xx`~`25:14` 로 적혀 있다(운행일 기준). 슬롯은 24시간으로 접어 배정한다.
- **급행(급행여부=1, 1호선 경인·경부 급행과 9호선 급행 1,273대)은 제외한다.** 정차역을 건너뛰어 인접 구간이 아니다. 급행 노선은 후속.
- 도착이 앞 역 출발보다 이른 행 27건(K1602 등, 도착 `00:00:00` 자리표시)은 그 쌍만 표본에서 제외하고 한 줄 집계 경고를 남긴다. 출발 시각이 멀쩡해 새 기준으로는 계산되지만, 그 값이 같은 구간 다른 열차보다 30~60초 짧아 열 자체를 믿을 수 없다. 표본이 구간마다 172~537개라 빼도 중앙값은 그대로이고, 이 경고를 남겨 두면 다음 파일에서 자리표시가 늘 때 바로 보인다.
- **출발 시각이 도착보다 이른 행 27건**(`00:00:00` 자리표시)은 출발 시각이 없는 것으로 보고 도착 시각으로 정렬한다. 고치기 전에는 정렬키가 0 이라 그 정차들이 맨 앞으로 몰려 순서를 흐트러뜨렸고, 4호선 안산선에 없는 구간 8개를 만들었다(반월→한대앞·한대앞→고잔·고잔→신길온천·신길온천→수리산은 8시간대 값, **정왕→안산 240초·초지→중앙 180초·중앙→상록수 210초·상록수→산본 480초는 중간 역을 건너뛴 지름길이라 경로 탐색이 실제로 골랐다**).
- **표본이 그 노선 구간 표본 중앙값의 10% 도 안 되는 구간은 버린다** (`MIN_SUPPORT_SHARE`). 5호선 회송 열차 70대는 두 역만 기록돼 있어(방화 출발 → 화곡 도착, 중간 6역 없음) 건너뛴 구간 10개를 만들었다: 방화→화곡 660초, 마천→둔촌동 650초, 둔촌동↔상일동, 상일동↔강동, 하남검단산↔미사, 상일동→하남풍산, 둔촌동→천호, 하남검단산→상일동. 실제 구간은 표본 59~630개로 기준(노선별 32~63)을 크게 넘어 하나도 걸리지 않고, 버린 뒤에도 5호선 실제 인접 체인은 전부 양방향 246개 이상 남는다. 노선별로 재는 이유는 지선·연장 구간의 운행 대수가 노선마다 달라서다.
- 1호선이 102역인 이유: 코레일 운영 구간(인천·신창·연천 방면)까지 들어 있다. 3호선 일산선, 4호선 진접선·과천안산선, 7호선 부천·석남, 8호선 별내도 포함된다. 코레일 열차(열차코드 K…)도 들어 있어 이 구간의 배차는 두 운영사 열차를 합친 값이다.

## 거리 기반 구간 규칙 (`KtdbLinkSegmentParser`, 시각표 밖 노선 — S15P21A104-113)

- 대상 노선 = 전체노선 파일에 있으면서 시각표가 덮지 않는 노선 중 line_id(실시간 API subwayId)가 있는 것. 지금은 9개: 경의중앙·수인분당·경춘·경강·서해·공항철도·신분당·우이신설·신림. 인천1·2·의정부·에버라인·김포골드·자기부상·GTX-A 는 subwayId 가 없어 건너뛰고 한 줄로 경고한다(GTX-A 는 코드 확인 뒤 후속).
- KTDB 링크 1개 = 인접 역 1쌍, `length_km` = 선로 거리. 노드 이름은 "판교역(신분당)" 꼴이라 괄호와 끝의 '역'을 떼고 별칭을 적용한다(`StationNameNormalizer.normalizeStation`). 링크는 한 방향만 있으므로 무방향 구간으로 만들어 빌더가 양방향 엣지를 만든다.
- **분기 노드**("분기(수색직결선_경의)"·"분기(용산삼각선_경원)")는 역이 아니다. 같은 노선의 앞뒤 링크를 이어 거리를 합친다(한국항공대→분기→수색 1.7+1.7 = 3.4 km). 링크가 셋 이상 걸린 분기는 어느 쪽을 이을지 몰라 버리고 경고한다.
- **`travel_sec` = 거리 ÷ 노선별 표정속도**(`conf/line-speeds.csv`, 없으면 `load.avg-speed-mps` 9.2), 최소 30초, `source=avg`. 속도는 운영사·언론이 공표한 전 구간 소요시간 ÷ KTDB 링크 경로 거리라 정차시간이 포함된 값이다. `wait_sec` 은 0 — 배차 원천이 없으면 채우지 않는다.
- 같은 (노선, 역 쌍)에 링크가 둘이면(상봉역(경춘)·상봉역(일반)) 첫 값을 쓰고, 거리가 100 m 넘게 다르면 경고한다.
- `conf/ktdb-link-overrides.csv` 로 두 가지 예외를 둔다: ① 서비스 노선명이 비어 있는 물리 링크에 노선 붙이기 — 경춘선 광운대 지선(망우선 4.3 km), 경의선 서울역 지선 가좌~신촌(경의선 물리 링크 2.7 km, 없으면 신촌·서울역이 떨어진 조각이 된다) ② `거리_km` 을 적어 KTDB 에 없는 링크 더하기(지금은 쓰는 행 없음).
- 파싱 뒤 노선별 역 집합을 전체노선 파일과 대조해 어느 한쪽에만 있는 역을 경고한다(서해선 원종은 KTDB 에만 있음 → 표준데이터 역번호 1981 로 표에 추가). 표에 없는 역이 나오면 적재가 멈추는 규칙은 그대로다.

## 식별자 규칙

- `station.station_id` = **서울교통공사 역번호** (`conf/station-ids.csv`, 2026-09-09 회의 결정). 물리 역 1행, 환승역은 소속 노선 코드 중 최솟값(서울 0150·0426 → `150`). 서울교통공사 코드가 없는 코레일·사철 전용 역은 **전국도시철도역사정보표준데이터의 역번호**(2026-09-10, S15P21A104-113: 코레일 4자리 1014·1501, 신분당 D004, 공항철도 A01, 우이신설 S110, 신림 S401. 1호선 코레일 구간 역은 시각표 역사코드가 곧 코레일 역번호라 회기 1015·광운대 1019 처럼 이미 같은 체계다). 옛 임시 부여 9001~9012 는 표준 번호로 이관했고(가천대 → 1851, 한남 → 1010 …) 표준데이터에 없는 도라산·양원만 9013·9014 다. `station.name` 은 정규화 역명(괄호 부기 제거 + 별칭)으로 표시용이다. 개명은 name 만 바뀌고 ID 는 유지된다. 노선별 승강장은 `edge_time.route_id` 로 표현한다.
- `line.line_id` = 서울시 실시간 지하철 API 의 `subwayId` (1001~1009, 1063 경의중앙, 1075 수인분당 …). 수집기가 변환 없이 쓰기 위해서다.
- 실시간 API 의 `statnId` 는 `subwayId(4) + 역코드(6, 0 채움)` 이다. 시각표의 `역사코드`(4자리, 예 0150)는 좌표 파일의 "고유역번호"(150)와 같은 체계다. **1호선 실시간 코드(126~133)는 다르다.** 수집기 티켓에서 매핑 표를 만든다.

## 알려진 빈 곳 (채워 넣지 않고 비워 둔 것)

- **좌표 출처가 섞여 있다**: 서울교통공사 역사 좌표 232 · 국가철도공단 역위치 242 · 표준데이터 90(다수결로 국가철도공단을 대체한 6개 포함) · KTDB 선로 노드 0. 어느 역이 어느 출처인지는 적재 로그 "역 좌표 출처" 줄에 나온다. 출처 컬럼(`coord_source`)은 스키마 변경이라 후속.
- **검토 필요 좌표**: 산본·한국항공대·송도는 표준데이터가 세 번째 원천이 되어 다수결로 정리됐다(113). 남는 "유지, 검토 필요" 경고는 적재 로그 "좌표 교차검증" 줄에 나온다.
- **시각표 밖 노선 9개는 `wait_sec = 0`** 이다(배차 원천 없음). 탐색이 대기를 더하기 시작하면 이 노선의 환승 대기는 0 으로 계산된다. TAGO 지하철정보 API(15098554) 활용신청 뒤 시각표를 받으면 같은 키를 `timetable` 이 덮는다 — 후속.
- **새 노선의 환승 도보 실측이 없다**: 왕십리·공덕·홍대입구·청량리·선릉·강남·판교 등 새로 환승역이 된 곳의 `transfer_meta` 행은 원천이 없어 넣지 않는다. 탐색은 180초 상수로 폴백한다(9호선·코레일 환승과 같은 처리).
- **GTX-A·인천1·2·의정부·에버라인·김포골드·자기부상(97역)은 적재하지 않는다**: 실시간 API subwayId 가 없어 `line_id` 를 정할 수 없다. GTX-A 는 코드 확인 뒤 후속. 전체노선 파일에는 다 있어 적재 로그가 "line_id 가 없는 노선 7개 건너뜀" 으로 알린다.
- **도라산·양원은 표준데이터에 없다**: 역번호를 임시 부여(9013·9014)했다. 표준데이터 다음 배포분에 들어오면 이관한다.
- **급행 열차**는 제외한다(위). 급행 구간을 별도 route 로 넣는 것은 후속 티켓.
- **하루 운행이 없는 (엣지, 요일)** 은 `wait_sec = 86400` 으로 표시한다 (전체 슬롯 행의 1.3%). 값을 만들어 넣지 않기 위한 표식이다.
- 환승 파일은 1~8호선 환승역만 담는다. 9호선·코레일 환승(노량진 1↔9, 김포공항 5↔9 등)의 도보 초는 원천이 없어 `transfer_meta` 에 없다.
- 일요일 막차 뒤 → 월요일 첫차의 대기는 같은 요일 유형(END)의 첫차 + 24시간으로 근사한다. 해당 슬롯은 어차피 운행이 없다.
