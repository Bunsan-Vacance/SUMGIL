# 혼잡도 정적 적재 원천 데이터

> `load` 프로파일의 로더(`com.ssafy.s15p21a104.load.crowd`)가 읽는 파일이다. 무료 공공데이터 원본이며
> 다운로드 후 **CP949 → UTF-8, CRLF → LF 변환만** 했다. 값은 건드리지 않았다 — 아래 "원천 결함"의 값도 파일에 그대로 있고 로더가 걸러낸다.
> 파일명 뒤 날짜는 제공처의 갱신 기준일이다. 새 배포분을 받으면 헤더를 대조하고 이 문서와 `StaticLoadRunner.CONGESTION_FILE` 을 함께 갱신한다.

## 읽는 규칙 (`CongestionParser`)

- **시각 열 → 30분 슬롯**: `5시30분` = 11, `8시30분` = 17, `23시30분` = 47, `00시00분` = 0, `00시30분` = 1. 커버 39/48이고 **01:00~05:29(슬롯 2~10)는 행을 만들지 않는다** — 표본 없는 구간에 값을 채우지 않는다(데이터 검증 리포트 원칙 1).
- **`STATION` = 그 물리 역의 모든 노선·방향 중 최대값.** 스키마에 방향이 없고, `station_id` 가 노선 코드 최솟값이라 환승역은 노선별 행이 한 ID 로 합쳐진다(서울역 1호선 `150` + 4호선 `426` → 둘 다 `150`. 1~8호선에 이런 역 35개). 최대를 쓰는 이유는 경로 추천에서 혼잡을 보수적으로 봐야 하고, 평균이 한 방향·한 노선의 극심을 희석하기 때문이다.
- **`LINE` = 그 노선 안에서만 계산한 평균.** (노선, 역) 단위 방향 최대를 노선별로 평균한다(소수 1자리). `STATION` 값을 재사용하면 환승역이 다른 노선 값을 끌고 들어와 노선 평균이 오염된다 — 첫 구현의 실제 결함이었고 `CongestionParserTest.transferStationContributesPerLine` 이 고정한다.
- `ROUTE` 타깃은 만들지 않는다 — 경로 개념이라 의미가 정해지지 않았다.
- **`level` 은 원천 그대로 저장한다.** 정원 대비 %라 100을 넘을 수 있다(원천 셀 340건, 최대 144.6). 적재 로그의 "100 초과"는 **원천 셀 기준**이고 DB `STATION` 행 기준은 331건이다 — 같은 물리 역·요일·슬롯에서 방향·노선이 겹쳐 최대 하나로 합쳐진 9건 차이다.
- 빈 칸·숫자가 아닌 값은 그 슬롯만 행을 만들지 않는다. 모르는 `구분`·`상하구분`은 건너뛰고 경고한다(원천 표기가 바뀌면 조용히 사라지지 않게).

## 역번호 → `station_id` (`CrowdStationCodes`)

혼잡도는 **노선별 역사코드**를 쓰고 우리 `station_id` 는 그중 **최솟값**이다. 그래서 `data/subway/conf/station-ids.csv` 의 `codes` 열("노선:코드;…")을 역방향으로 읽는다 — 앞 0 이 있는 표기와 없는 표기를 모두 키로 둔다.

| 혼잡도 | → `station_id` | 이유 |
| --- | --- | --- |
| `201` 시청(2호선) | `151` | 우리는 1호선 코드 `0151` 이 최솟값 |
| `426` 서울역(4호선) | `150` | 1호선 `0150` 이 최솟값 |
| `150` 서울역(1호선) | `150` | 그대로 맞는다 |

282개 (역번호, 호선) 쌍 중 276이 이렇게 매핑된다. 남는 6건은 서울교통공사가 **지선·순환 분기를 구분하려고 붙인 가상 역번호**로 어느 노선 코드에도 없다 — `conf/crowd-station-aliases.csv` 로 실제 역에 잇는다.

## 설정 파일 (`conf/`)

| 파일 | 역할 |

## 다시 받는 법

```bash
# 공공데이터포털 15071311 페이지의 다운로드 링크(atchFileId)를 쓴다. CP949 CSV 약 420 KB
curl -L "https://www.data.go.kr/cmm/cmm/fileDownload.do?atchFileId=FILE_000000003682445&fileDetailSn=1&insertDataPrcus=N" \
  | iconv -f CP949 -t UTF-8 | tr -d '\r' > BE/src/main/resources/data/crowd/seoulmetro-congestion_YYYYMMDD.csv
head -1 BE/src/main/resources/data/crowd/seoulmetro-congestion_YYYYMMDD.csv   # 헤더 대조 (시각 열이 39개인지)
# StaticLoadRunner.CONGESTION_FILE 과 이 문서를 갱신한다
```

분기 갱신이라 **역·시각 열이 늘거나 가상 역번호가 추가될 수 있다.** 모르는 역번호는 적재를 멈추지 않고 한 줄로 집계 경고하므로, 적재 로그의 "역 ID 표에 없는 역번호" 줄을 보고 별칭을 추가한다.

## 알려진 빈 곳 (채워 넣지 않고 비워 둔 것)

- **1~8호선만 있다.** 9호선·코레일 운행 구간·113 으로 넣은 9개 노선(148역) 등 324역은 혼잡도 행이 없다. 승하차 데이터로 추정하는 것은 AI CROWD 트랙의 몫이다(`AI/README.md` ⑥ 호선별 역별 시간대별 승하차).
- **01:00~05:29 슬롯이 없다.** 원천이 05:30부터 시작한다.
- **방향이 사라진다.** 스키마에 방향이 없어 상선·하선을 최대로 합친다. 방향별로 필요해지면 `congestion` 스키마 변경(타깃에 방향 추가)이 필요하다.
- **`bike_stock_pred` 는 비어 있다.** 73 에서 더미를 넣지 않기로 했다 — `BikeStockGate` 가 가짜 값으로 따릉이 경로를 걸러내기 시작하기 때문이다. AI 78 산출물 연동은 S15P21A104-115.
