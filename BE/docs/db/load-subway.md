# 지하철 정적 적재 (S15P21A104-69 · 70)

> `line` · `station` · `transfer_meta` · `edge_time`(SUBWAY) 을 공공데이터 파일에서 채우는 로더.
> 69 에서 골격(`load` 프로파일 · CsvTable · 그래프 빌더 · 검증 · JdbcTemplate upsert)을 만들고, 70 에서 **열차운행시각표를 1~9호선 엣지의 정본**으로 바꿨다 —
> 방향 있는 구간 + 요일×30분 슬롯별 `wait_sec`. 113 에서 **시각표 밖 수도권 노선 9개(경의중앙·수인분당·경춘·경강·서해·공항철도·신분당·우이신설·신림, 역 148개)** 를
> KTDB 철도망 링크의 선로 거리 ÷ 노선별 표정속도로 넣었다. 코드는 `com.ssafy.s15p21a104.load`, 원천과 설정은 `src/main/resources/data/subway/` (출처·열·규칙은 그 폴더 README).

## 실행

```bash
# 1) DB 기동 (저장소 루트)
docker compose -f Infra/docker/docker-compose.yml up -d postgres

# 2) 적재 (BE 폴더). local 프로파일이 없으면 DB_URL·DB_USERNAME·DB_PASSWORD 환경변수로 대신한다
cd BE
SPRING_PROFILES_ACTIVE=local,load ./gradlew bootRun --args='--load.sources=subway --load.dry-run=true'   # 파싱·검증·건수·prune 예정만
SPRING_PROFILES_ACTIVE=local,load ./gradlew bootRun --args='--load.sources=subway'                        # 실제 적재 + prune
SPRING_PROFILES_ACTIVE=local,load ./gradlew bootRun                                                        # 지하철·버스·따릉이 전부
```

| 옵션 | 기본 | 뜻 |
| --- | --- | --- |
| `--load.dry-run` | false | DB 에 쓰지 않고 그래프 건수·검증 결과·prune 예정 엣지만 출력 |
| `--load.write-mode` | BATCH | `edge_time` 쓰기 방식. ROW 는 성능 비교용 baseline |
| `--load.prune` | true | 시각표가 덮는 노선(1001~1009)에서 이번 실행에 없는 `edge_time` 행과, 어느 엣지·환승에도 안 쓰이는 역을 지운다 |
| `--load.region` | (전부) | 포함할 line_id. 예 `--load.region=1002,1005`. 서비스 권역 확정 시 사용 |
| `--load.avg-speed-mps` | 9.2 | 시각표 밖 노선 거리 구간의 기본 표정속도. 노선별 값은 `conf/line-speeds.csv` 가 우선하고 표에 없는 노선에만 쓴다 |

- 프로파일은 **`local,load` 두 개**를 함께 준다. `logback-spring.xml` 이 `local`·`default`·`prod` 에만 콘솔 출력을 붙여 두어 `load` 만 주면 로그가 나오지 않는다.
- 몇 번 실행해도 결과가 같다 (자연키 `ON CONFLICT DO UPDATE` + prune, `updated_at` 은 실행 시각). 두 번째 실행의 prune 은 0건이다.
- 검증 오류가 하나라도 있으면 아무것도 쓰지 않고 예외로 끝난다. 경고는 로그로만 남긴다.
- 시각표 42만 행은 gzip 을 스트리밍으로 읽어(`CsvTable.forEachRow`) 행을 메모리에 쌓지 않는다. 파싱 약 7초.

## TAGO 역별 시각표 — 시각표 밖 9개 노선의 `wait_sec` (S15P21A104-243, 2026-09-18)

113 으로 넣은 9개 노선은 열차운행시각표(서울교통공사 1~9호선)에 없어 `wait_sec = 0` 이었다. 190 이 첫 승차 대기를 소요시간에 더하기 시작하면서
이 노선으로 시작하는 경로가 첫 대기만큼 부당하게 유리해졌다(버스 배차간격 228 과 같은 편향). 원천은 **공공데이터포털 15098554 국토교통부_(TAGO)_지하철정보**의
역별 시간표다 — 열차 번호 없이 "이 역에서 어느 행선지로 언제 떠나는가" 만 준다. 그래서 `travel_sec` 은 못 만들고(거리 ÷ 표정속도 그대로) `wait_sec` 만 붙인다.

N 에서 출발해 from 을 지나지 않고 행선지에 닿으면 — from→N 의 출발로 본다(노선 이웃 관계는 KTDB 구간에서, BFS). 분기 노선(경의중앙 서울역 지선,
경춘 광운대 지선)도 이 규칙으로 갈린다. 행선지를 노선 역 목록에서 못 찾거나 비어 있으면 세 단계로 대체한다 — ① 같은 역·같은 U/D 에서 풀린 행들의
다수결 이웃, ② 노선 전체에서 그 U/D 가 향한 종점의 다수결(그 종점이 어느 이웃 너머인지), ③ 이웃이 둘인 역에서 반대 U/D 가 풀린 이웃의 나머지. 전부 실패하면
버리고 센다. **서해선은 역마다 한쪽 U/D 의 행선지가 비어 온다**(2,968행 — 초지 U 처럼 행선지 없이 시각만) — ②가 없으면 서해선 한 방향이 통째로 빠진다.
행선지가 그 역 자신이면 종착 열차라 건너뛴다. 시각은 `HHmmss` 문자열이고 자정 넘는 열차는 `00xxxx` 로 오는데 `SlotWaits` 가 24시간으로
접으므로 운행일 보정 없이 넣는다. 결과는 `"lineId|출발역|도착역"` → `SlotWaits` 로, 열차운행시각표의 키와 같은 형식이라 `SubwayGraphBuilder` 가 그대로
station_id 키로 바꾼다. 시각표 노선의 키는 건드리지 않는다(`putIfAbsent`).

**표기.** `edge_time.source` 는 `avg` 를 유지한다 — 그 열은 `travel_sec` 의 근거(거리 ÷ 표정속도)를 말하고, `wait_sec` 이 시각표 기반이라는 사실은 이 문서와
적재 로그("TAGO 시각표: … 대기 붙인 방향 엣지 N/448")로 남긴다. 열을 나누는 스키마 변경은 하지 않았다.

## 식별자·값 규칙

- **`station.station_id` = 서울교통공사 역번호** (2026-09-09 회의 결정, S15P21A104-103). `conf/station-ids.csv` 가 정본: 노선별 역사코드 최솟값에서 앞 0 을 뗀 값(서울 `150`, 시청 `151`, 강남 `222`, 김포공항 `2513`). 서울교통공사 코드가 없는 코레일·사철 전용 역은 **전국도시철도역사정보표준데이터의 역번호**(113: 청량리 `1014`, 판교 `1501`, 신사 `D004`, 공항철도 서울 `A01`, 우이신설 `S110`, 신림 `S401`) — 1호선 코레일 구간 역은 시각표 역사코드가 곧 코레일 역번호라(회기 `1015`, 광운대 `1019`) 이미 같은 체계였다. 70 시점의 임시 부여 `9001`~`9012`(가천대·한남 등)는 113 에서 표준 번호로 이관했고, 표준데이터에 없는 도라산·양원만 `9013`·`9014` 다. 물리 역 1행, 동명이역은 별개 행(신촌 2호선 `240` / 경의중앙 `1252`, 양평 5호선 `2523` / 경의중앙 `1217`). `station.name` 은 정규화 역명(표시용). 개명은 name 만 바뀌고 ID 는 유지된다. 표에 없는 역이 나오면 적재가 멈춘다 — ID 가 몰래 생기지 않게. 69~70 의 "정규화 역명 = ID" 규칙은 103 에서 폐기됐고 첫 적재의 prune 이 옛 ID 행(엣지 954·환승 199·역 416)을 지웠다.
- `line.line_id` = 실시간 지하철 API `subwayId`. 수집기가 변환 없이 route_id 로 쓴다. subwayId 가 없는 노선(인천1·2·의정부·에버라인·김포골드·자기부상·GTX-A)은 적재하지 않는다.
- **엣지는 방향이 있다.** 시각표 구간은 그 방향 열차가 있을 때만 생긴다(2호선 순환·6호선 응암순환). KTDB 거리 구간(시각표 밖 노선)만 양방향이다.
- **`edge_time.travel_sec` = 다음 역 출발 − 이 역 출발** 의 열차별 중앙값 (`source=timetable`, S15P21A104-111). 도착이 아니라 출발까지 재므로 **도착역 정차시간(중앙값 30초, 9호선 25초)이 들어간다.** 종착역은 출발 시각이 없어 도착으로 잰다. 정차를 도착역 쪽에 붙이는 이유는 `wait_sec` 이 출발 시각 기준이라 출발역 정차가 이미 지나간 시간이기 때문이다 — 대신 경로의 마지막 구간에서 목적지 정차 1회(약 30초)를 더 센다. **시각표 밖 노선은 KTDB 링크 선로 거리 ÷ 노선별 표정속도**(`conf/line-speeds.csv`, `source=avg`, 최소 30초, 113).
  - 표정속도는 운영사·언론이 공표한 전 구간 소요시간 ÷ KTDB 경로 거리라 정차 포함 값이다: 경강 19.4(판교~여주 48분) · 경춘 16.4(춘천~상봉 82.5분) · 공항철도 16.3(일반 66분) · 신분당 14.0(강남~광교 37분) · 서해 11.6(일산~원시 68분) · 수인분당 10.9(청량리~인천 163분) · 경의중앙 9.9(문산~용문 약 180분) · 우이신설 8.0(23분) · 신림 7.8(16분). 표에 없는 노선은 9.2(서울교통공사 1.1 km ≈ 2분; 거리와 시각표가 둘 다 있는 1·4호선 148구간 실측은 10.5). 시각표를 확보한 노선부터 `timetable` 이 덮는다.
- **`edge_time.wait_sec` = 슬롯 안 임의 시각 도착 시 다음 열차 출발까지의 기대 대기(초).** 배차가 고르면 배차간격 ÷ 2 와 같고, 열차가 없는 슬롯은 첫차까지의 대기가 된다. 막차 뒤는 같은 요일 유형의 첫차 + 24시간으로 잇는다. 하루 운행이 없는 (엣지, 요일)은 **86,400** 표식(1.3%). 1~9호선은 열차운행시각표, 시각표 밖 9개 노선은 TAGO 역별 시각표(243)에서 같은 정의로 계산한다. TAGO 에도 없는 역에서 출발하는 `avg` 엣지만 0(원천 없음).
- 요일: 시각표 DAY/SAT/END = `dow_type` 0/1/2. 자정 넘는 24:xx 표기는 24시간으로 접어 0~2번 슬롯에 들어간다.
- 급행(1호선·9호선 1,273대)은 제외한다. 도착 ≤ 출발인 이상치 27건은 표본에서 뺀다.
- **유령 구간을 만들지 않는다** (S15P21A104-111). 출발 시각이 도착보다 이른 행 27건(`00:00:00` 자리표시)은 출발 없이 다룬다 — 정렬키 0 으로 맨 앞에 몰려 4호선 안산선에 없는 구간 8개를 만들었고 그중 정왕→안산·초지→중앙·중앙→상록수·상록수→산본은 중간 역을 건너뛴 지름길이라 탐색이 실제로 골랐다. 표본이 그 노선 중앙값의 10% 도 안 되는 구간 10개(5호선 회송 열차가 두 역만 남긴 방화→화곡 등)도 버린다. 두 규칙 다 건수·예시를 한 줄로 집계해 경고하고, 실행 로그의 "표본 부족 제외" 에 건수가 나온다.
- `transfer_meta.walk_sec` 는 서울교통공사 환승거리 ÷ 1.2 m/s 값 그대로. 9호선·코레일·113 으로 새로 환승역이 된 곳(왕십리↔수인분당, 공덕↔공항철도, 판교 신분당↔경강 …)은 원천이 없어 없다 — 탐색은 180초 상수로 폴백한다.
- ~~시각표 밖 노선 9개의 `wait_sec` 은 0 이다~~ → **243(2026-09-18)부터 TAGO 역별 시각표로 채운다** (아래 "TAGO 역별 시각표" 절). `travel_sec` 은 여전히 거리 ÷ 표정속도(`source=avg`)고 `wait_sec` 만 시각표 기반이다. TAGO 에 시각표가 없는 역(경춘 20역·경의중앙 용산·금릉·도라산, 수인분당 신길온천)에서 출발하는 엣지는 여전히 0 이다.

## 읽는 쪽에 미치는 영향 (경로 탐색)

- **역 ID 형식이 바뀌었다**: `originStationId`·`destStationId`·`edge_time.from_node/to_node`·`transfer_meta.station_id`·Redis `reversal:{origin}:{dest}:…` 키에 들어가는 값이 한글 역명(`강남`)에서 역번호(`222`)가 됐다. 앞 0 은 없다(`0222` 아님). 역 이름은 `station.name`(`RouteNameMapper`)에서 읽는다. 표: `data/subway/conf/station-ids.csv`.
- `RouteEdgeTimeRepository.findSubwayEdgesForDefaultSlot()` 은 대표 슬롯 (dow 0, slot 0) 하나만 읽는다. 이제 슬롯마다 `wait_sec` 이 다르고 0번 슬롯(00:00~00:30)은 배차가 길다. **요청 시각의 (dow_type, time_slot) 로 조회해야 한다.** 행은 지우지 않으므로 "행 없음"으로 깨지지는 않는다.
- 역 ID 변경: 당고개 → 불암산, 지제 → 평택지제. 1호선 서울~구로 등 엣지 224개·역 79개 추가. 6호선 응암순환은 단방향.
- `wait_sec = 86400` 은 그 요일에 운행이 없다는 뜻이다. 비용으로 그대로 더하면 자연히 피해 간다.
- **`travel_sec` 이 구간마다 약 30초 커졌다** (S15P21A104-111, 정차시간 포함). 경로 소요가 시각표 실제와 맞아진다: 강변→역삼 11분 → 15분, 역삼→합정 28분 30초 → 38분 30초. 포트폴리오·성능 문서의 경로 소요 수치를 다시 뽑을 때 이 기준을 쓴다.
- **유령 구간 18개가 prune 됐다** (4호선 안산선 8 + 5호선 회송 10). 그전에는 중간 역을 건너뛴 지름길이 더 빨라서 탐색이 그걸 골랐고, 응답 경로에서 역이 빠져 보였다.
- **역 148개·노선 9개가 추가됐다** (S15P21A104-113). 경의중앙·수인분당·경춘·경강·서해·공항철도·신분당·우이신설·신림의 역이 출발·도착으로 검색되고, 기존 역 50개가 새 노선의 환승역이 됐다(왕십리·공덕·홍대입구·청량리·선릉·강남·판교 …). 이 노선들의 `edge_time` 은 `source=avg`(거리 ÷ 노선별 표정속도)이고 **`wait_sec` 은 0** 이다 — 탑승 대기를 더할 때 이 노선의 환승 대기는 0 으로 계산된다. 새 환승역의 `transfer_meta` 행은 없어 `TransferRule` 이 180초 상수로 폴백한다.
- **임시 ID 9001~9012 가 표준데이터 역번호로 바뀌었다** (위 표). 이 ID 를 캐시·하드코딩한 곳이 있으면 갱신해야 한다. 동명이역 신촌·양평은 이름 검색에서 두 건이 나온다.
- **좌표 10건이 바뀌었다** (위 표). 지도 표시가 달라진다: **용답이 6.4 km 이동**(시청 자리 → 장한평 인근)하고, 10 m 거리로 겹쳐 보였던 잠실새내·잠실나루가 1,850 m로 떨어진다. 대여소 거리 계산(`BikeEdgeBuilder`)이 기동 시 `station` 좌표를 읽으므로 재기동으로 반영된다 — 용답에 붙던 시내 대여소가 49곳 → 19곳으로 줄어 잘못된 BIKE 엣지 60개가 사라진다.
