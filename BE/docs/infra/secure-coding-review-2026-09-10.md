시연용 배포를 준비하면서 코드베이스를 OWASP Top 10 기준으로 훑어봤다. **치명적인 문제는 없었고**, 실제 배포 전에 확인/결정하면 좋을 항목만 정리한다.

## 상세

### 1. SQL/JPQL 인젝션 — 문제없음

- 컨트롤러→서비스→레포지토리 전부 JPA 파생 쿼리 또는 `@Query`의 `:param` 바인딩만 사용(`StationSearchServiceTest`, `RouteEdgeTimeRepository` 등).
- `UpsertWriter`(정적 데이터 적재 전용, HTTP로 노출 안 됨)에 `IN (?,?,?)` 형태로 문자열을 조립하는 부분이 있는데, **값이 아니라 자리표시자(`?`) 개수만** 문자열로 만들고 실제 값은 `jdbc.query(sql, ..., args.toArray())`로 바인딩한다 — IN절 동적 생성의 표준 안전 패턴이다.

### 2. 에러 응답 — 문제없음

- `GlobalExceptionHandler`가 모든 예외를 고정된 `ErrorType` 메시지로만 응답한다. `exception.getMessage()`는 서버 로그(`log.warn`)에만 쓰고 응답 바디에는 절대 안 넣는다. 스택트레이스도 클라이언트에 안 나간다.

### 3. 시크릿 관리 — 문제없음

- `application.yml`은 `${DB_URL}` 같은 환경변수 참조만 있고 실제 값이 없다.
- `application-local.yml`(실제 로컬 접속 정보)과 `.env`는 `.gitignore`에 있고, git에 커밋된 적 없음(확인함).
- `.env.example`엔 로컬 개발용 더미 값(`sumgil1234`, docker-compose 기본값과 동일)만 있고 외부 API 키는 전부 빈 값.

### 4. CORS — 문제없음

- `CorsConfig`가 `/api/**`에 대해 출처를 정확히 나열(`app.cors.allowed-origins`)한다. 와일드카드(`*`) 미사용.

### 5. 인증/인가 — 없음 (설계상 의도, 배포 전 확인 필요)

- 모든 API가 인증 없이 열려 있다. 지금까지 팀 결정상 로그인 기능 자체가 범위 밖이라 당연한 상태지만, **시연용이라도 배포되면 외부에서 접근 가능**하다는 뜻이다.
- 위험도는 낮다 — 개인정보를 다루지 않고(역·정류소·대여소 위치는 공개 정보), 쓰기 API도 없다(전부 GET 조회). 그래도 팀 확인 차 남겨둔다: "인증 없이 공개해도 되는 데이터만 다루는 게 맞다"는 걸 명시적으로 동의하고 넘어가는 게 좋겠다.

### 6. Swagger UI / Actuator 노출 — 배포 전 결정 필요

- 부팅 로그에 Spring Boot가 직접 경고한다: `springdoc.api-docs.enabled=false`/`springdoc.swagger-ui.enabled=false`를 프로덕션에서 고려하라고.
- 지금 `management.endpoints.web.exposure.include: health,info`로 최소한만 열어뒀다(전체 actuator 엔드포인트 노출 아님 — 안전한 편).
- **결정 필요**: 시연용 배포에서 Swagger UI(`/swagger-ui.html`)를 계속 열어둘지. 팀 시연 중 API 구조를 직접 보여주고 싶으면 켜두는 게 오히려 유용할 수 있음 — 이건 보안 문제라기보단 "의도적으로 켜둘지" 선택의 문제.

### 7. Rate limiting — 없음

- 어떤 엔드포인트에도 요청 제한이 없다. 오늘 부하 테스트(`scripts/loadtest/`)로 300 동시 요청까지 에러 없이 버티는 걸 확인했으니, 시연 규모에선 실질적 위험은 낮다. 다만 배포 후 URL이 팀 밖으로 새어나가면 무제한 요청이 가능하다는 점은 인지하고 있는 게 좋다.

### 8. 의존성 취약점 스캔 — 미실시

- Spring Boot 4.1.1 등 버전 자체는 최신이라 눈에 띄는 문제는 없었지만, OWASP Dependency-Check 같은 자동 스캔 도구는 안 돌려봤다(그레이들 플러그인 추가+네트워크 조회 필요, 이번엔 범위 밖으로 뒀다). 필요하면 별도로 붙일 수 있다.

## 배포 전 팀 확인 필요 항목 (요약)

1. 인증 없이 공개 데이터만 다루는 현재 설계, 시연 배포에도 그대로 괜찮은지
2. Swagger UI를 시연 배포에서 켜둘지 끌지
3. (선택) 의존성 취약점 자동 스캔 도구 도입 여부
