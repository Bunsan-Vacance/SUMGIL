## 2. 빌드 시 환경 변수

**BE** (`BE/.env` — 로컬 개발용, `BE/.env.example`이 키 목록 원본)

| 변수 | 설명 |
| --- | --- |
| `DB_URL`, `DB_USERNAME`, `DB_PASSWORD` | PostgreSQL 접속 정보 |
| `REDIS_HOST`, `REDIS_PORT` | Redis 접속 정보 |
| `KAFKA_BOOTSTRAP_SERVERS` | Kafka 브로커 주소 (수집기·컨슈머 프로파일에서만 필요) |
| `SEOUL_API_KEY`, `SEOUL_SUBWAY_KEY`, `SEOUL_BIKE_KEY` | 서울 열린데이터광장 인증키 |
| `DATA_GO_KR_KEY` | 공공데이터포털(data.go.kr) 디코딩 키 — 버스 도착정보 |
| `KAKAO_REST_API_KEY` | 카카오맵 도보 경로 조회 REST API 키 |
| `SPLUNK_HEC_URL`, `SPLUNK_HEC_TOKEN` | (선택) 개인 로컬 Splunk 데모 전용, 비워도 기동에 지장 없음 |

값이 비어 있어도 애플리케이션은 기동한다 — 해당 기능만 "정보 없음"으로 비활성화된다(예: `KAKAO_REST_API_KEY` 없으면 도보 geometry가 `unavailable`로 남는다).

**FE** (`FE/.env.local` — `FE/.env.example`이 키 목록 원본)

| 변수 | 설명 |
| --- | --- |
| `VITE_KAKAO_MAP_APP_KEY` | Kakao Developers JavaScript 키. 허용 도메인에 배포 도메인을 등록해야 지도가 뜬다 |
| `VITE_API_BASE_URL` | BE API 베이스 URL (미설정 시 샘플 데이터로 동작) |

**AI** (`AI/k8s/prod/ai-secret.env` — `ai-secret.env.example`이 키 목록 원본)

| 변수 | 설명 |
| --- | --- |
| `CROWD_LLM_API_KEY` | (실험 축) 혼잡도 LLM 예측기용, 미사용 시 비워둔다 |
| `TIME_LLM_API_KEY` 또는 `GMS_API_KEY` | 재안내 에이전트(TIME)가 호출하는 LLM 게이트웨이(GMS, OpenAI 호환) 키 |

**빌드 명령**

```bash
# BE
cd BE
./gradlew build            # 테스트 포함 전체 빌드
./gradlew bootJar          # 실행 가능 JAR만

# FE
cd FE
npm ci
npm run build              # tsc --noEmit && vite build

# AI (서빙 이미지는 아직 미구축 — 로컬 실행 시)
cd AI
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

## 3. 배포 시 특이사항

- **배포 방식**: EC2 2대(control-plane 1 + worker 1)에 k3s를 올려 단일 `prod` 네임스페이스에서 운영한다. 소스 배포가 아니라 **컨테이너 이미지 + Kubernetes 매니페스트(Kustomize)** 방식이다.
- **자동 배포(CI/CD)**: GitLab CI가 각 파트의 `develop-*` 브랜치에 커밋이 올라오면 자동으로 이미지 빌드 → 클러스터 내장 레지스트리 push → `kubectl apply -k` 순으로 배포한다(`.gitlab/ci/deploy.yml`). `develop-BE` → BE 워크로드, `develop-FE` → FE 워크로드, `main` 변경분 중 `Infra/**` → 인프라 계층이 대상이다. **AI는 아직 Dockerfile·이미지가 없어 자동 배포 대상이 아니다** — 매니페스트 뼈대만 존재한다(`AI/k8s/prod/ai.yaml`).
- **단일 인스턴스 고정**: 데이터 계층 상주로 EC2 리소스 여유가 크지 않아 BE는 `replicas: 1`로 고정 운영한다. 수평 확장은 미적용.
- **도메인·라우팅**: `j15a104.p.ssafy.io` 단일 호스트, `/` → FE, `/api/` → BE, TLS는 클러스터 내부에서 cert-manager로 종결한다.
- **이미지 태그**: 커밋 short SHA를 태그로 쓴다(`latest` 고정 사용 안 함) — 같은 태그를 재배포해도 새 코드가 반영되지 않는 실수를 방지하기 위함이다.
- **서버사이드 적용(SSA) 소유권 충돌 주의**: `kubectl scale`처럼 명령형으로 리소스를 직접 건드리면 그 필드의 소유권이 CI의 선언적 apply와 충돌해 이후 배포가 막힌다. 배포 파이프라인은 `--force-conflicts`로 항상 매니페스트 선언값이 이기도록 방어해뒀다(`.gitlab/ci/deploy.yml`).
- **수동 배포가 필요할 때**: `Infra/README.md`의 절차(`Infra/k8s/scripts/deploy/apply.sh`, `build-push.sh`)를 순서대로 실행한다. Secret 파일은 GitLab 변수에서 렌더링하며(`render-secrets.sh`), 저장소에는 `*-secret.env.example`만 커밋되어 있다.
- **수집기 호출 한도**: 서울 열린데이터광장·공공데이터포털 API 키는 하루 호출 한도(대략 1,000회/키)가 있다. 로컬 개발과 prod가 같은 키를 공유하는 구간이 있으므로, 로컬에서 수집기 프로파일(`collect`)을 켜둔 채 장시간 테스트하면 prod 수집이 실패할 수 있다.

## 4. DB 접속 정보 및 주요 설정 파일 목록

| 파일 | 내용 |
| --- | --- |
| `BE/.env.example` | 로컬 개발용 전체 환경변수 키 목록(값은 비어 있음) |
| `BE/k8s/prod/be-config.env` | 운영 비민감 설정(ConfigMap 원본, 커밋됨) |
| `BE/k8s/prod/be-secret.env.example` | 운영 비밀값 키 목록(값은 별도 채널로 전달, 커밋 안 함) |
| `Infra/k8s/prod/data-secret.env.example` | DB 비밀번호(`DB_PASSWORD`) 키 목록 — 데이터 계층(Infra) 소유, BE·AI가 공유 소비 |
| `BE/src/main/resources/application.yml` 및 `application-*.yml` | 프로파일별 Spring 설정(수집기·컨슈머 등) |
| `BE/src/main/resources/db/migration/V1~V6__*.sql` | Flyway 스키마 마이그레이션(자동 적용, 수동 실행 불필요) |
| `BE/docs/db/schema.md` | 테이블 설계·용어 정의 문서 |
| `AI/k8s/prod/ai-secret.env.example` | AI 비밀 키 목록 |
| `FE/.env.example` | FE 환경변수 키 목록 |

DB 접속 기본값(로컬 docker-compose 기준): `jdbc:postgresql://localhost:5432/sumgil`, 계정 `sumgil` / 비밀번호는 `.env`(로컬)·`data-secret.env`(운영)로 별도 전달한다(저장소 미포함).
