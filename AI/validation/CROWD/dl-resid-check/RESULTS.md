# 144 — 딥러닝 시계열(GRU) 잔차 예측 모델

**한 줄 결론.** GRU는 `full`(이력 완비)에서 LightGBM 배포 세트보다 **RMSE 16.4/11.6%p 낮다**(기각 방향).
대신 **이력이 짧거나 없을 때 붕괴하지 않는다** — `no_lag`에서 LightGBM은 lookup 대비 RMSE −36.6/−40.7%인데
절단 증강 GRU는 −7.9/−3.9%, 등급 일치율은 lookup과 같은 95.34%(LightGBM 91.49%)다. 144는 구현·기록까지고
채택 판정은 145다.

## 2. 모델 정의

```
예측 = lookup(요일유형×역×시간대 평균) + GRU가 낸 z-잔차 × std(역, 슬롯)

표본  (역, 대상일) 1개
입력  x_seq  [14, 20, 7]  = z-잔차 2(승·하차) + 마스크 1 + 그 날 요일유형 one-hot 4
      x_stat [9]          = 대상일 요일유형 4 + 대상일 이벤트 5(학습 구간 표준화)
      station            → 임베딩 273→16
모델  GRU(hidden 64, 1층, 입력 20×7=140) → h_N ⊕ emb ⊕ x_stat → Linear(128) → ReLU → Linear(40) → [20, 2]
손실  Huber(δ=1, z 단위), 실측이 있는 슬롯만(`y_mask`) 평균
```

- **z-정규화**: 역×슬롯별 학습 구간 잔차 표준편차로 나눈다(하한 1.0). 역마다 잔차 규모가 30배 차이라
  정규화 없이는 큰 역이 손실을 독식한다. 스케일 표는 아티팩트 `scale.parquet`에 남아 역변환에 쓰인다.
- **마스크 채널**: 없는 날은 값 0 + 마스크 0이다. **0은 "0명"이 아니라 마스크가 "없음"을 말한다**(원칙 8).
- **이력 절단 증강(`gru`)**: 표본마다 `k ~ U{0..14}`로 앞쪽 k일을 마스크(`masking.sample_truncation`
  + `truncate_history`). `gru_no_trunc`는 이 증강만 뺀 대조군이고 나머지는 전부 같다.
- 쓰지 않은 것: `lag1s`(직전 슬롯)·인접역 열(D−1 원천 전제 = 배포 세트와 정보량 동일), 하이퍼파라미터
  탐색(hidden 64 고정, 검증 손실로 **에폭만** 선택), Transformer 계열.

## 4. 판정 기준 대비 관찰

기준은 144 계획에 **사전 고정**된 것이다. 144의 완료 조건(학습 1회 → 아티팩트 → `build_predictor("dl")`로
2025 평가, 4시나리오 표, 학습 시간·시드 기록)은 전부 충족했다. 채택 판정은 145다.

- **(a) `full`에서 GRU는 LightGBM ±2%p 이내일 것 → 불충족(RMSE), 근접(MAE·등급).**
  RMSE는 −16.39%p(승) / −11.64%p(하)로 크게 벗어난다. 다만 MAE는 −4.88 / −4.50%p, 등급 일치율은
  **+0.08%p로 동등**이다. "승하차 RMSE"라는 지표 하나로만 보면 기각이고, 서비스 산출물(등급)로 보면 무승부다.
  145는 어느 지표로 채택을 판정할지 먼저 정해야 한다.
- **(b) 절단 증강 GRU는 `no_lag`에서 lookup 대비 0%p 이상, `d7_only`에서 양수일 것 → 부분 충족.**
  RMSE 기준으로는 `no_lag` −7.92 / −3.94, `d7_only` −5.78 / −1.59로 **여전히 음수**라 문자 그대로는 불충족이다.
  그러나 (i) MAE는 `d7_only`에서 +2.02 / +2.74로 양수, `no_lag`에서 −1.5 / −0.5로 거의 0, (ii) 등급 일치율은
  `no_lag`에서 lookup과 같고, (iii) 같은 조건의 LightGBM(−36.6 / −40.7)·대조군(−34.9 / −48.7) 대비
  **+28.7 / +36.8%p**다. "이력 결손 시 붕괴하지 않는다"는 성질 자체는 확인됐고, "lookup보다 낫다"까지는 못 갔다.
- **(c) 절단 증강이 `full`을 1%p 이상 깎으면 가용성별 모델 2개 안(145) → 승차에서만 트리거.**
  `full` RMSE는 승차 +6.99(증강) vs +10.38(대조)로 **−3.39%p**, 하차는 +13.72 vs +6.70으로 **+7.02%p**다.
  방향이 승·하차에서 반대라 "증강이 full을 깎는다"는 해석은 이 한 쌍의 학습만으로는 단정할 수 없다 —
  시드 1개(42)만 돌렸고 두 학습의 검증 손실 차이(0.2917 vs 0.2903)가 이 격차를 설명하지 못한다.
  145가 이 항목을 쓰려면 **시드 3개 이상 반복**이 먼저다.

## 5. 미해결 · 145로 넘기는 것

1. **판정 지표 확정.** RMSE(기각) / MAE(근접) / 등급 일치율(동등)이 서로 다른 답을 준다. 145 채택 기준
   "RMSE·MAE 둘 다 +2%p"를 그대로 쓰면 GRU는 탈락이고, 그러면 "이력 결손 시 대체 모델"이라는 쓸모가 버려진다.
2. **가용성별 예측기 선택(하이브리드).** 배치는 이미 이력 일수를 알고 있다(`meta.history_days_present`,
   `lag1d_available`). `full`이면 LightGBM, 이력이 모자라면 GRU, 전무하면 lookup으로 고르는 3단 규칙이
   두 모델의 좋은 쪽만 쓴다 — 지금은 이력이 없으면 lookup으로 떨어뜨리는 143 규칙만 있다.
3. **RMSE 격차의 원인.** z-정규화 + Huber(δ=1)가 큰 잔차의 기울기를 눌렀을 가능성. δ를 키우거나 z 대신
   원 단위 손실을 쓰는 1파라미터 실험이 남았다(144는 하이퍼파라미터 탐색을 하지 않기로 했다).
4. **2호선 열세.** GRU만 `full`에서 lookup보다 나쁜 유일한 호선(−6.16%). 역 임베딩 차원·지선 방향 체계와
   엮인 문제인지 확인이 필요하다.
5. **시드 반복 없음.** 결정성은 확인했지만(같은 시드 재현 0.000%) **시드 간 분산은 재지 않았다.** (c)의 판단과
   `full` 승·하차 비대칭이 여기 걸려 있다.
6. **`lagsd_*` 비대칭.** `d1_only`·`d7_only`에서 LightGBM은 `lagsd_*`(같은 요일유형 직전 날, ≤14일)를 같이
   버린다 — 시퀀스의 한 날에 대응하지 않기 때문이다. 그만큼 LightGBM 쪽이 불리하게 잡혀 있고, `full`·`no_lag`는
   영향이 없다.
7. **lookup 기준선의 검증 구간 포함.** 파생 캐시의 잔차는 **2024 전체**로 fit한 lookup 기준이다(LightGBM
   아티팩트와 같은 정의). 144의 검증 구간(2024-11~12)이 그 평균에 들어가 있어 early stopping에 아주 약한
   누수가 있다. 파생을 다시 만들지 않기로 한 제약(계획) 때문이고, **2025 평가에는 영향이 없다**.
8. **`--predictor dl`이 대조군을 집는다.** `latest_artifact(kind="dl")`는 계열 안에서 폴더명 정렬 최신을 고르는데
   `dl_gru_s14_notrunc_…`가 `dl_gru_s14_…`보다 뒤라 대조군이 선택된다(배치 스모크에서 확인). `auto`는 lightgbm만
   보므로 운영에는 영향이 없지만, 145에서 DL을 쓰기로 하면 대조군 폴더를 옮기거나 이름 규칙을 손봐야 한다.
9. **LSTM 1회 실험은 끝났다(위 3절).** GRU와 구분되지 않아 계열 이름은 `gru`로 확정한다 —
   145는 `lstm`을 별도 계열로 세우지 않는다(145 계획 보정 4와 같은 결론).
