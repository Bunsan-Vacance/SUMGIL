# 통계 모형 비교 검증 — lookup·LightGBM 대 계절 나이브·OLS-AR·SARIMA(X)

S15P21A104-145의 **통계 모형** 파트만(LLM·DL은 범위 밖). 브랜치 `feat/CROWD-stat-model-check`.
스크립트 `stat_models.py`(순수 로직) · `predict_all.py`(계열별 예측) · `evaluate.py`(표·CI).

> ⚠️ **잠정 결과 — 1~8절 수치를 인용·판정 근거로 쓰지 않는다.** 2026-09-16 로컬 실행에 쓴 패널이
> 88번 요일유형 버그가 고쳐지기 **전** 판이었다(토·일이 전부 `휴일`로 흡수돼 `day_type` 2종,
> `app/CROWD/pipeline/calendar.py` docstring 참고). lookup이 토·일을 구분하지 못하면 1주 전 시차가 그 주간
> 패턴을 대신 메워, **선형 AR·SARIMAX의 재현율(4절)이 부풀려졌을 가능성이 크다.** 최신 패널로 다시 돌린
> 결과로 1~8절을 전면 교체한다 — 절차는 **9절 재실행 계획**.

## 0. 질문 · 사전 가설 · 판정 기준(실행 전 고정)

### 질문

배포 모델 = `lookup(요일유형×역×시간대 평균) + LightGBM(잔차의 전날·같은요일유형직전·1주전 시차 +
이벤트 + 범주)`. 이 구조는 "잔차에 AR 항을 건 모델"의 비선형 판이라고 볼 수 있다. 그렇다면

1. 고전 시계열 모형(계절 나이브, SARIMA)은 lookup을 이기는가?
2. **같은 시차 정보를 선형으로만 쓰면**(OLS-AR, SARIMAX 잔차) LightGBM 개선분(+23~25%, MODEL_REGISTRY
   2절)의 몇 %가 재현되는가? → LightGBM의 기여를 "시차 정보 자체"와 "비선형·범주 상호작용"으로 분해한다.

### 비교 계열(모두 2025 평가, D−1 정보만, 파라미터는 2024로 적합)

| 이름 | 정의 |
| --- | --- |
| `lookup` | 요일유형×역×시간대 평균(2024 적합). 기준선 |
| `snaive_d7` | 같은 (역,시간대)의 **원본값** 7일 전 |
| `ols_pooled` | 잔차 = β·[lag1d, lagsd, lag7d] 선형회귀, 타깃별 1개(전역 적합) |
| `ols_series` | 위와 같되 (역,시간대,타깃)마다 따로 적합. 유효행 < 30이면 그 시리즈 NaN |
| `sarima_raw` | (역,시간대,타깃) 원본 시계열 SARIMAX(1,0,1)(0,1,1,7). lookup 도움 없음 |
| `sarimax_resid` | 같은 시계열의 lookup 잔차 SARIMAX(1,0,0)(1,0,0,7)+상수. 예측=lookup+잔차예측 |
| `lightgbm` | 배포 세트 `festival_selflag_d1sd_d7_resid` 아티팩트(로컬 재학습) |

### 사전 가설(H1~H4, 결과로만 채택/기각 판정)

- **H1.** 계절 나이브(`y_{d−7}`)는 lookup보다 **나쁘다**(하루치 노이즈를 그대로 옮긴다).
- **H2.** 원본 SARIMA(`sarima_raw`, lookup 없이)는 lookup과 비슷하거나 조금 낫고, LightGBM에는 크게
  못 미친다.
- **H3.** 잔차 선형 AR(`ols_pooled`/`ols_series`, 같은 시차 3종)은 LightGBM 개선분의 **절반 이상**을
  재현한다.
- **H4.** SARIMAX(잔차, `sarimax_resid`)는 시리즈별 OLS-AR(`ols_series`)과 2%p 이내로 같다(상태공간이
  추가로 주는 것이 적다).

### 판정 기준(티켓 145 사전 고정 준용)

통계 모형이 LightGBM을 **대체**하려면, 전체 RMSE·MAE **둘 다** LightGBM과의 쌍 부트스트랩 차이 CI가
LightGBM 쪽으로 불리하지 않고(하한 > −2%p) 어느 호선·요일유형도 2%p 넘게 악화하지 않아야 한다.
그 외는 LightGBM 유지 — H1~H4는 "대체 여부"가 아니라 "기여 분해"를 답하기 위한 것이라, 대체 판정과
별개로 채택/기각을 명시한다.

### 로컬 재현의 알려진 제약(실행 전 명시)

- 로컬 conda base 환경(pandas 3.0.5, statsmodels 신규 설치), 학습 PC(Windows·SUMGIL)와 다르다.
- **로컬 패널의 `day_type`은 `평일`/`휴일` 2종뿐이다**(학습 PC 산출물인 `significance-check/RESULTS.md`
  4절은 `평일/토요일/일요일/휴일` 4종을 쓴다). `DayTypeLookupBaseline`의 조회 키에 `day_type`이
  들어가므로 lookup 테이블의 그룹 세분도 자체가 다르다 — LightGBM·lookup 재현치가 MODEL_REGISTRY의
  +23.38/+25.36과 달라질 근거가 이미 여기 있다. 쫓지 않고 로컬 재현값을 기준으로 모든 비교를 한다.
- 모델 아티팩트·파생 캐시·배율표가 로컬에 없어 LightGBM은 새로 학습하고, 등급 일치율(표 C 등급 절)은
  배율표가 없으면 건너뛴다.
- SARIMA는 90분 규칙(계획 §2)에 따라 표본 이후 전체 실행 여부를 실행 중 결정한다 — 이 절 작성
  시점에는 아직 실행 전이라 표본/전체 여부는 결과 절에 채운다.

- **LightGBM 로컬 재현값은 27.50/29.12(RMSE), 35.26/34.03(MAE)** — MODEL_REGISTRY의 +23.38/+25.36(RMSE),
  +29.56/+28.42(MAE)보다 전부 높다. 1절의 `day_type` 이분법 차이가 가장 유력한 원인이다(로컬 lookup이
  더 거칠어 기준선이 약하고, 모든 모델의 상대 개선율이 커 보인다). **쫓지 않고 이 로컬 재현값을 기준으로

- `snaive_d7`은 RMSE·MAE 모두 CI가 사실상 0 아래(MAE만 상단이 살짝 0을 걸침) — 하루치 노이즈를 그대로
  옮긴다는 H1이 그대로 확인된다.
- `sarima_raw`(원본 SARIMA, lookup 미사용)는 **RMSE로는 lookup보다 나쁘고**(하차는 CI가 완전히 음수),
  **MAE로는 오히려 낫다**(+18%대, CI가 0 위). 왜 갈리는지는 6절에서 논의.
  단, DM(날짜별 평균제곱오차 차이)은 유의하지 않다(p=0.12~0.29) — RMSE 부트스트랩 CI와 DM이 서로 다른
  결론을 내는 것처럼 보이는데, 6절에서 이유를 남긴다(미해결).
- `ols_pooled`·`ols_series`·`sarimax_resid`는 모두 RMSE·MAE 둘 다 CI가 0 위 — lookup을 확실히 이긴다.

**전체 축에서는 어느 통계 모형도 대체 기준을 만족하지 못한다** — `sarimax_resid`는 RMSE로는 LightGBM과
사실상 동률(CI가 0을 포함)이지만 MAE에서 LightGBM에 3%p대로 뒤진다. 판정 기준(RMSE·MAE 둘 다 하한
>−2%p)이 요구하는 것은 "둘 다"라 MAE가 발목을 잡는다.

**예외 — 1호선.** `ols_series`·`sarimax_resid`가 1호선에서는 LightGBM을 **유의하게 이긴다**(대체 가능 =
예): `ols_series` RMSE +8.27[6.38,10.12](하) / +9.75[7.63,11.76](승), `sarimax_resid` RMSE +7.67[5.94,9.43]
(하) / +10.55[8.07,12.82](승) — 계열이 LightGBM보다 크다는 뜻(양수 = 계열이 더 낫다). MAE도 대부분 CI
하한이 −2%p 위다. 다른 7개 호선은 전부 LightGBM이 유의하게 앞선다(계열 diff 음수, CI가 0 아래). 1호선이
왜 다른지는 이번 범위에서 규명하지 못했다(6절 미해결) — MODEL_REGISTRY의 호선별 표(142)는 1호선을
LightGBM의 약점으로 짚지 않았어서(6호선이 최저), 로컬 재현(다른 `day_type` 이분법)에서 새로 나타난
현상일 수 있다.

## 4. 표 C — LightGBM 개선분 재현율(전체, 승·하)

| 계열 | 재현율 RMSE % (승/하) | 재현율 MAE % (승/하) |
| --- | --- | --- |
| `snaive_d7` | −235.7 / −269.8 | −24.2 / −30.0 |
| `ols_pooled` | 84.3 / 85.0 | 75.5 / 79.4 |
| `ols_series` | 94.5 / 95.2 | 85.6 / 87.8 |
| `sarima_raw` | −41.1 / −70.1 | 51.5 / 52.9 |

**시차 정보 자체(선형)가 LightGBM 개선분의 대부분(RMSE 84~99%, MAE 76~90%)을 이미 설명한다.**
LightGBM이 추가로 얹는 "비선형·범주 상호작용"의 몫은 RMSE 기준 1~16%p, MAE 기준 10~25%p로, 시차
정보 자체의 기여보다 뚜렷이 작다 — H3가 가정한 "절반 이상"보다 훨씬 크게 재현된다.

## 6. 판정 — H1~H4

| 가설 | 판정 | 근거 |
| --- | --- | --- |
| **H1**(계절 나이브 < lookup) | **채택** | RMSE 전체 −64.81/−78.56%, CI가 사실상 0 아래. 원인 그대로(하루치 노이즈 이전) |
| **H2**(원본 SARIMA ≈/조금 > lookup, ≪ LightGBM) | **기각** | RMSE는 lookup보다 **나쁘다**(−11.3/−20.4%, 하차 CI 완전히 음수) — "비슷하거나 조금 낫다"와 어긋난다. MAE는 반대로 lookup보다 낫다(+18%대). "LightGBM에 크게 못 미친다"는 부분만 맞다(재현율 RMSE 음수, MAE 51~53%) |
| **H3**(잔차 선형 AR이 LightGBM 개선분의 절반 이상 재현) | **채택**(예상보다 강하게) | `ols_pooled` 84~85%(RMSE)/76~79%(MAE), `ols_series` 95%/86~88% — "절반 이상"을 크게 넘는다 |
| **H4**(SARIMAX(잔차) ≈ 시리즈별 OLS, 2%p 이내) | **채택** | 전체 RMSE 차이 0.9~1.2%p, MAE 차이 0.9~1.7%p — 모두 2%p 이내. 상태공간이 추가로 주는 것은 적다 |

**대체 판정(티켓 145 기준).** 전체 축에서 통계 모형 중 LightGBM 대체 기준(RMSE·MAE 둘 다 쌍차이 CI
하한 > −2%p)을 만족하는 것은 없다 — **LightGBM 유지.** 단 1호선 단일 노선에서는 `ols_series`·
`sarimax_resid`가 유의하게 낫다(3절) — 호선별 모델 교체는 이번 범위 밖이라 다음 티켓 후보로만 남긴다.

## 8. 미해결

- **`sarima_raw`의 RMSE 부트스트랩 CI와 DM 검정이 서로 다른 결론을 낸다.** 표 A에서 RMSE 개선율 CI는
  하차 기준 완전히 음수([−38.36,−3.35])인데, 같은 데이터의 DM(날짜별 평균제곱오차 차이)은 유의하지
  않다(p=0.12). RMSE는 SSE를 날짜별로 합산한 뒤 제곱근을 취하는 비선형 집계라 부트스트랩 표본분포가
  치우칠 수 있고, DM은 날짜별 평균의 선형(HAC) 검정이라 서로 다른 귀무가설을 본다 — 어느 쪽이
  "맞다"의 문제라기보다 두 통계량이 답하는 질문이 다르다는 뜻이지만, 정확한 원인(발산 정리 후 잔존
  분산 구조, 날짜별 SSE의 두꺼운 꼬리 등)은 규명하지 못했다.
  다음 검증에서 날짜별 SSE 분포를 직접 그려보는 것을 권한다.
- **1호선에서만 통계 모형이 LightGBM을 이기는 이유**(3절)를 규명하지 못했다. 로컬 `day_type` 이분법
  차이 때문인지, 1호선 자체의 특성(가장 긴 노선·완행/급행 혼재) 때문인지 구분이 필요하다.

- **등급 일치율(표 C 등급 절)을 내지 못했다** — `data/CROWD/processed/crowd_congestion_calibration.parquet`
