# 통계 모형 비교 검증 — lookup·LightGBM 대 계절 나이브·OLS-AR·SARIMA(X)

S15P21A104-145의 **통계 모형** 파트만(LLM·DL은 범위 밖). 브랜치 `feat/CROWD-stat-model-check`.
스크립트 `stat_models.py`(순수 로직) · `predict_all.py`(계열별 예측) · `evaluate.py`(표·CI).

수치는 **학습 PC(Windows·SUMGIL)에서 88번 요일유형 수정판 패널로 재실행한 결과**다. 맥에서 낸 잠정
수치(요일유형 2종 패널 + 이벤트 열 누락 + 발산 행 제외)는 전부 폐기했다 — 무엇이 틀렸고 얼마나
달라졌는지는 1절에 남긴다.

## 0. 질문 · 사전 가설 · 판정 기준(실행 전 고정)

### 질문

배포 모델 = `lookup(요일유형×역×시간대 평균) + LightGBM(잔차의 전날·같은요일유형직전·1주전 시차 +
이벤트 + 범주)`. 이 구조는 "잔차에 AR 항을 건 모델"의 비선형 판이라고 볼 수 있다. 그렇다면

1. 고전 시계열 모형(계절 나이브, SARIMA)은 lookup을 이기는가?
2. **같은 시차 정보를 선형으로만 쓰면**(OLS-AR, SARIMAX 잔차) LightGBM 개선분(+23~25%, MODEL_REGISTRY
   2절)의 몇 %가 재현되는가? → LightGBM의 기여를 "시차 정보 자체"와 "비선형·범주 상호작용"으로 분해한다.

### 비교 계열(모두 2025 평가, D−1 정보만, 파라미터는 2024로 적합)

| 이름 | 정의 |
| --- | --- |
| `lookup` | 요일유형×역×시간대 평균(2024 적합). 기준선 |
| `snaive_d7` | 같은 (역,시간대)의 **원본값** 7일 전 |
| `ols_pooled` | 잔차 = β·[lag1d, lagsd, lag7d] 선형회귀, 타깃별 1개(전역 적합) |
| `ols_series` | 위와 같되 (역,시간대,타깃)마다 따로 적합. 유효행 < 30이면 그 시리즈 NaN |
| `sarima_raw` | (역,시간대,타깃) 원본 시계열 SARIMAX(1,0,1)(0,1,1,7). lookup 도움 없음 |
| `sarimax_resid` | 같은 시계열의 lookup 잔차 SARIMAX(1,0,0)(1,0,0,7)+상수. 예측=lookup+잔차예측 |
| `lightgbm` | 배포 세트 `festival_selflag_d1sd_d7_resid` 아티팩트 |

### 사전 가설(H1~H4, 결과로만 채택/기각 판정)

- **H1.** 계절 나이브(`y_{d−7}`)는 lookup보다 **나쁘다**(하루치 노이즈를 그대로 옮긴다).
- **H2.** 원본 SARIMA(`sarima_raw`, lookup 없이)는 lookup과 비슷하거나 조금 낫고, LightGBM에는 크게
  못 미친다.
- **H3.** 잔차 선형 AR(`ols_pooled`/`ols_series`, 같은 시차 3종)은 LightGBM 개선분의 **절반 이상**을
  재현한다.
- **H4.** SARIMAX(잔차, `sarimax_resid`)는 시리즈별 OLS-AR(`ols_series`)과 2%p 이내로 같다(상태공간이
  추가로 주는 것이 적다).

### 판정 기준(티켓 145 사전 고정 준용)

통계 모형이 LightGBM을 **대체**하려면, 전체 RMSE·MAE **둘 다** LightGBM과의 쌍 부트스트랩 차이 CI가
LightGBM 쪽으로 불리하지 않고(하한 > −2%p) 어느 호선·요일유형도 2%p 넘게 악화하지 않아야 한다.
그 외는 LightGBM 유지 — H1~H4는 "대체 여부"가 아니라 "기여 분해"를 답하기 위한 것이라, 대체 판정과
별개로 채택/기각을 명시한다.

### 1.2 맥 결과가 틀어진 두 원인

1. **요일유형 2종 패널**(이미 알려진 것) — 88번 버그 수정 전 판이라 토·일이 `휴일`로 흡수돼 lookup이

2. **평가 프레임에 이벤트 5열이 없었다**(새로 찾은 것) — `predict_all.DERIVED_COLS`가 배포 세트 13열 중
   시차 6열만 읽어, `features.build_matrix`가 나머지를 조용히 NaN으로 채웠다(`build_matrix`는 서빙에서
   실시간 열이 아직 없을 때를 위해 없는 컬럼을 NaN으로 두는 설계다). 그 결과 **비교 대상인 LightGBM만
   이벤트 정보 없이 예측**했고 RMSE 개선율이 +23.38 → **+21.80**(승) / +25.36 → **+23.40**(하)로 낮아져
   있었다. 지금은 세트 피처 전부를 읽고, 예측 직전에 `stat_models.missing_feature_columns`로 누락을
   막는다(누락이 있으면 실행을 멈춘다).

### 1.4 발산 — 늦게 개통한 역 하나가 원인이고, 제약을 켜면 사라진다

`enforce_stationarity=False`로 두면 결측 구간에서 개루프로 전파되며 물리적으로 불가능한 값이 나온다
(적합 자체는 `ok=True`라 실패 집계에 잡히지 않는다). **발산 행은 전부 역 2810(암사역사공원, 8호선)
한 곳**이었다 — 이 역은 패널이 2024-07-31에 시작하는(늦게 개통한) 역이라 앞쪽이 통째로 결측이다.

| 역 2810, 2025 | 발산 행(승/하) | 예측 최댓값(승/하) | 클립 후 RMSE(승/하) |
| --- | --- | --- | --- |
| `sarima_raw` 제약 끔 | 365 / 365 | 1.34e25 / 1.15e64 | 3,932.9 / 4,519.5 |
| `sarima_raw` 제약 켬 | **0 / 0** | 1,740 / 1,300 | **90.5 / 61.5** |
| `sarimax_resid` 제약 끔 | 365 / 669 | 2.0e120 / 3.16e143 | 3,964.2 / 6,083.8 |

전체 273역에서도 같다(표 G). **그래서 제약을 켠 쪽을 본 설정으로 쓴다**(계획 §9 3단계 그대로).
제약 없는 쪽은 `--no-enforce-stationarity`(`_noenf`)로만 남긴다.

**발산 처리 규칙(`--divergence`).** 상한은 **2024 학습 구간 실측 최댓값**에서만 정한다(평가 구간을 보지
않는다): 승차 17,788 / 하차 20,476. 주 표는 `clip` — 예측을 `[0, 상한]`으로 자른 값으로 **채점에
포함**한다. 맥에서 쓴 `drop`(상한 초과를 결측으로 되돌려 제외)은 그 모형의 최악 오차를 평가에서 없애
그 모형에 유리하다. **제약을 켠 본 설정에서는 상한 초과가 0건이라 `clip`과 `drop`의 표 A~D가 완전히
같다**(민감도 확인 완료). 하한 0은 물리 제약이고 서빙 변환 층도 같은 자리에서 자른다 — 걸린 행은
`lightgbm` 9,304/2,243, `sarima_raw` 6,165/2,969, `sarimax_resid` 1,995/1,383, `ols_pooled` 1,849/1,057,
`ols_series` 1,106/700(승/하).

**시차 정보를 선형으로만 써도 LightGBM 개선분이 거의 다 재현된다** — 전역 1개 모델로도 RMSE 89~91%,

## 8. 판정 — H1~H4와 대체 여부

| 가설 | 판정 | 근거 |
| --- | --- | --- |
| **H1**(계절 나이브 < lookup) | **채택** | 전체 RMSE −72.07 / −86.17%, MAE도 −19~−20%, CI 전부 0 아래 |
| **H2**(원본 SARIMA ≈/조금 > lookup, ≪ LightGBM) | **채택** | RMSE는 lookup과 구분 불가(CI가 0 포함, DM p=0.38~0.56), MAE는 +12%대로 낫다 → "비슷하거나 조금 낫다". LightGBM 재현율은 RMSE 음수·MAE 40%대로 "크게 못 미친다" |
| **H3**(잔차 선형 AR이 LightGBM 개선분의 절반 이상 재현) | **채택**(예상보다 훨씬 강하게) | `ols_pooled` RMSE 90.6/89.0%, `ols_series` 102.5/101.2% |
| **H4**(SARIMAX(잔차) ≈ 시리즈별 OLS, 2%p 이내) | **채택** | RMSE 차 0.86/0.66%p, MAE 차 1.52/1.52%p — 모두 2%p 이내 |

**대체 판정: LightGBM 유지.** 조건 두 개 중 하나가 걸린다.

- 전체 축(하한 > −2%p): `ols_series` **통과**, 나머지는 탈락.
- 슬라이스(어느 호선·요일유형도 2%p 넘게 악화 없음): `ols_series`는 **7호선 −4.13%p(하한 −5.99)**,
  **공휴일 −4.97/−6.30%p**로 **탈락**. 등급 일치율도 LightGBM이 가장 높다(표 E).

즉 "전체 평균으로는 선형 시차 모형이 배포 모델과 동등하지만, 약한 구간이 특정 호선·공휴일에 몰려
있어 교체하지 않는다"가 이번 결론이다. 반대로 **1호선은 선형 모형이 +13~17%p 앞선다** — 호선별 모델
교체는 이번 범위 밖이라 후속 티켓 후보로만 남긴다(93의 호선별 분할 실험은 LightGBM 안에서만 비교했고
기각됐다 — 선형 모형으로 1호선만 갈아 끼우는 안은 아직 시험하지 않았다).

## 10. 미해결

- **1호선에서만 선형 시차 모형이 LightGBM을 크게 이기는 이유**(+13~17%p)를 규명하지 못했다. 패널
  판본 문제가 아님은 확인됐다(수정판에서 재현). 1호선의 특성(가장 긴 노선, 완행·급행 혼재, 199에서
  절단면 경계 유입을 따로 보정한 노선)과 연결해 봐야 한다.
- **공휴일에서 선형 모형이 뒤지는 폭**(−5~6%p)이 LightGBM의 이벤트·범주 상호작용 때문인지, 공휴일
  표본이 18일뿐이라 CI가 넓은 탓인지 분리하지 못했다(공휴일 CI 하한 −12%p까지 벌어진다).
- **92 표본과 전체 축의 순위 역전**(5절)을 더 파지 않았다. `snaive_d7`까지 표본에서 앞서는 것을 보면
  표본 추출 자체가 변동이 큰 역·날짜에 쏠려 있다 — 92·145의 표본 정의를 다시 볼 여지가 있다.
- **노트북 산출물은 만들지 않았다**(계획 §7) — 추후 `_build_notebook.py` 방식으로 이 폴더에 추가한다.

  부정확)로 슬라이스 판정은 부트스트랩 CI만 근거로 했다(DM은 전체 축 참고용).
