# crowd-snapshot-eda

`AI/data/CROWD/`에 받아둔 혼잡도 원천(서울시 CSV 1종 + 9호선 xlsx 7종)의 EDA. PoC 단계이며
`app/CROWD/`(프로덕션)으로 승격하기 전 단계다.

## 데이터 실체 — 시계열이 아니라 "대표 1주 스냅샷"이다

두 원천 모두 `(호선/역/방향/요일유형[/급행-일반]) × 30분 시간대`의 혼잡도(%) 표다. 그런데
9호선 xlsx 안에는 이런 안내가 박혀 있다:

> `(기준일자 : '24.11.18.(월)~11.22.(금))` — 평일 값의 근거가 된 대표 1주
> `(기준일자 : '24.11.23.(토)~11.24.(일))` — 휴일 값의 근거가 된 대표 1주

즉 날짜 컬럼이 없고, 각 값은 **특정 대표 1주를 관측해 만든 평균치**다. 연도별 파일을 쌓아도
"역×시간대×요일유형"당 연 1~2개 관측치만 늘 뿐이라, 이 데이터만으로 특정 날짜의 날씨·이벤트와
상관분석을 하는 것은 불가능하다 — 대표주간 자체가 날씨·이벤트와 무관하게 뽑힌 임의의 한 주라
날짜에 매핑할 수 없다.

날짜 축이 있는 진짜 일별 시계열이 필요하면 `AI/README.md` 4절의 **⑥ 호선별 역별 시간대별
승하차(`CardSubwayTime`)**가 후보다. 파이프라인 구상: 승하차(일별, 동적) → 이 혼잡도 스냅샷을
보정계수로 스케일링 → 외부요인(날씨·이벤트)은 승하차 시계열에 조인해 상관분석한다. 상관분석의
타깃은 "혼잡도%"가 아니라 "일별 승하차량(또는 평시 대비 배율)"이어야 한다.

## 파일 크기 이상치

`9호선 2020년.xlsx` 등 2020~2022년 파일은 14MB지만 실제 데이터는 40행 안쪽이다(2024/2025년
파일과 동일). 엑셀 서식이 시트 전체 범위(최대 104만 행)까지 적용된 잔재이지 데이터가 많아서가
아니다. `dataset.py`의 `load_line9_workbook`은 이 상태에서도 정상 동작하지만, 로드가
느리게 느껴지면 이게 원인이다.

## EDA 진행 순서

1. **정적 프로파일 EDA** — `dataset.py`로 두 원천을 tidy long-format으로 합쳐 역×시간대×
   요일유형 피벗, 결측·이상치(0%, 100%+ 등) 확인. 연도별 스냅샷 비교는 추세 참고용으로만
   본다(일 단위 상관분석 대상 아님).
2. **동적 신호 확보** — `CardSubwayTime` 실제 다운로드(범위를 먼저 정하고 실행 —
   `AI/CLAUDE.md` 하드룰), 날짜 범위·결측·역 커버리지 확인.
3. **보정계수 추정** — 같은 요일유형·시간대에서 혼잡도(%) 스냅샷과 승하차량의 비율을
   역별로 추정해 "승하차량 → 혼잡도 추정치" 변환식을 만든다.
4. **외부요인 조인 + 상관** — 기상청 실황, 서울시 행사·야구 일정을 승하차 시계열에 붙여
   상관·기여도를 검사한다. 표본이 부족한 역·이벤트 조합은 값을 채우지 않고 "데이터 부족"으로
   남긴다([데이터 검증 리포트 원칙](../../../../Docs/Service%20Design/데이터-검증-리포트.md#5-검증에서-도출된-원칙)).
5. 상관이 유의미한 요인만 실시간 예측 입력으로 채택한다.

## 실행 (Python 설치 후)

```bash
pip install -r ../../../requirements-dev.txt
python
>>> from dataset import load_seoul_congestion_csv, load_line9_workbook
>>> seoul = load_seoul_congestion_csv("../../../data/CROWD/서울교통공사_지하철혼잡도정보.csv")
>>> line9_2024 = load_line9_workbook("../../../data/CROWD/2024년 9호선 역별 시간별 혼잡도 자료.xlsx", year=2024)
```

로직이 검증되면 이 EDA는 노트북(`.ipynb`)으로 옮겨 시각화를 붙이고, 승격할 부분은
`app/CROWD/service.py` 또는 `pipeline/`으로 이동한다.
