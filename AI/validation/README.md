# validation/

PoC · 스파이크 코드 전용 — **`app/`(프로덕션)이 아니다.** 기존 `notebooks/`의 탐색적 분석(EDA)과
모델 후보 검증 스크립트가 여기로 들어간다.

## 관례

- `app/`과 같은 도메인 이름으로 폴더를 나눈다 (`CROWD/`, `BIKE/`, `ROUTE/`).
- 파인튜닝·검증형 스파이크는 `<기능>-check/` 디렉터리명을 쓰고, 전처리(`dataset.py`) + 실행
  스크립트 + 평가 스크립트로 나눈다.
- 모델 후보·설정은 중앙 레지스트리(`{"이름": 경로 또는 ID}` dict + `ACTIVE_*` 상수)로 관리해
  키 하나만 바꾸면 스왑되게 한다.
- 무거운 의존성(torch 등)은 함수 내부에서 지연 import한다 — 모듈 최상단 import로 인한 로딩
  지연·불필요한 네트워크 I/O를 막기 위해서다.
- 노트북 출력은 커밋 전에 비운다. diff가 읽히지 않는다.
- 학습 산출물(체크포인트, 재생성 가능한 데이터셋)은 커밋하지 않는다.
- 검증이 끝나 프로덕션으로 승격할 로직은 `app/<도메인>/service.py` 또는
  `app/<도메인>/pipeline/`으로 옮긴다. 반대 방향(`app/`이 `validation/`을 import)은 하지 않는다.
