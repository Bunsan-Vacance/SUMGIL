# 백엔드 연동 피드백 (2026-09-10)

## FE 확인 결과

- `GET /api/routes/search`와 `GET /api/bike-stations/nearby`를 `VITE_API_BASE_URL`로 연결한다.
- 실제 API 경로에는 프론트가 검색 요청 시 기록한 시각과 서버의 `totalMinutes`로 도착 예정 시각을 계산한다. 샘플 모드에서만 기존 `09:41` 기준을 유지한다.
- 서버 응답에 없는 도보 거리·혼잡도·노선 표기는 화면에서 숨긴다. 혼잡도가 없으면 `덜 붐빔 우선` 정렬은 비활성화한다.
- `geometry`의 `MultiLineString` 구조와 `geometryStatus`는 수용한다. `unavailable`인 경우 직선으로 대체하지 않고 선을 표시하지 않는다.
- `/api/stations/search`의 역별 `stationId`와 노선 정보를 사용해 경로 입력 결과를 서버 역 ID로 전달한다. 일반 장소 검색 결과는 임의로 역에 매핑하지 않는다.
- 1063 노선 구간은 제공된 geometry를 지도에 표시하고, 역사 내부 구간처럼 `TRANSFER` geometry가 `unavailable`인 경우에는 환승 지점 marker만 표시한다.
- 현재는 시간 우선으로 진행하고, 시간·혼잡도 혼합 정렬은 후속 논의로 둔다.
- 대여소 검색 반경 3km와 범위를 벗어난 요청의 400 응답은 현재 계약으로 수용한다. 최대 결과 100건 제한도 수용한다.

## 후속 협의

- 혼잡도 필드와 기준 시각은 별도 계약이 필요하다. 계약 전에는 서버 응답에 없는 값을 프론트에서 만들지 않는다.
- 지하철 단일 노선 외 혼합 경로(`SHORTEST_WITH_BIKE`)는 서버 지원 시 화면에서 제공한다.

## 오류 안내

현재 화면은 역 간 경로만 지원한다. 역이 아닌 장소를 선택하면 서버 요청 전에 역을 선택하라는 안내를 표시하며, 서버의 `SAME_ORIGIN_DEST`·`STATION_NOT_FOUND` 오류 코드는 사용자용 안내 문구로 변환해 표시한다.
