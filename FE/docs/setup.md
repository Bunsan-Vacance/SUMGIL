# 숨길 React 화면 미리보기

`02-sugil-mvp-wireframe-revised.html`에서 합의한 화면을 React 컴포넌트로 구현했다. HTML을 삽입하는 방식이 아닌 React 상태와 컴포넌트로 구성한다.

## 실행

Node.js 22.12 이상 또는 24 LTS를 사용한다. 저장소 루트에서:

```powershell
cd FE
npm ci
npm run dev
```

기본 개발 서버는 http://localhost:5173 을 열며, 현재 원본 작업 트리의 실제 FE 검증은 http://localhost:5174 에서 수행한다. 기존 `local-stack/FE` 사본은 5173 실행용이다. 현재 카카오 키에서 localhost 도메인의 지도 로딩을 확인했다. 127.0.0.1을 쓰려면 해당 도메인도 카카오 콘솔에 등록해야 한다. 배포용 빌드는 `npm run build`, 경로 데이터 검증은 `npm test`로 실행한다.

## 카카오 지도 설정

`.env.example`을 `.env.local`로 복사하고 `VITE_KAKAO_MAP_APP_KEY`에 카카오 앱의 **JavaScript 키**를 입력한다. REST API 키나 Admin 키는 사용하지 않는다. `.env.local`은 Git에서 제외된다.

실제 경로·대여소 API를 사용하려면 `.env.local`의 `VITE_API_BASE_URL`을 `http://localhost:8080`으로 설정한다. 값을 바꾼 뒤 개발 서버를 다시 시작한다.

경로 검색 계약을 로컬에서 확인할 때는 `VITE_API_BASE_URL`을 유지하고 `VITE_ROUTE_SEARCH_MOCK=true`를 추가한다. 경로 검색만 `ApiResult` envelope와 `source: MOCK` fixture를 사용하며 역·장소·대여소 API 연결은 유지한다. 운영 환경에서는 이 값을 `true`로 설정하지 않는다.

샘플 경로에는 `congestionPrediction`과 구간 전환 예시가 포함된다. 퍼센트 0과 100 초과를 보존하고, 예측값이 없으면 `예측 정보 없음`을 표시한다. 모든 값은 서울 기준 D+0~D+3 예상값이며 혼잡 사유 설명은 제공하지 않는다. 백엔드 전달 계약은 [FE-BE-통합-API-계약](../../../FE-BE-통합-API-계약.md)에서 확인한다.

도착 시 따릉이 예측을 미리보기로 확인할 때는 `VITE_BIKE_PREDICTION_MOCK=true`를 추가한다. 이 flag가 없고 `VITE_API_BASE_URL`이 있으면 `/api/bike-stations/{rentalId}/prediction`을 실제 호출하며, 라이브 오류를 mock으로 대체하지 않는다. 최신 로컬 BE에는 이 endpoint가 아직 없다.

카카오 개발자 콘솔에서 해당 JavaScript 키의 SDK 도메인으로 `http://127.0.0.1:5173`, `http://localhost:5173`, `http://127.0.0.1:5174`, `http://localhost:5174`를 등록한다. 키를 입력한 후 개발 서버를 다시 시작한다. [공식 설정 가이드](https://apis.map.kakao.com/web/guide/) 참고.

실제 지도의 이동·확대·축소, 출발/도착 장소 검색을 통한 마커 표시, 현재 위치 조회를 연결했다. 홈에 진입하거나 다시 들어오면 현재 위치를 1회 조회하고, 지도에서 현재 위치 버튼을 눌러 다시 조회할 수 있다. 지도 영역은 바텀시트 높이에 맞게 변경하여 지도 출처 표시가 시트에 가려지지 않도록 한다.

지도 SDK는 경로를 계산하지 않는다. 경로 API 연결 전까지 임의 경로선은 그리지 않는다. 지도 로드 실패 시 다시 시도할 수 있다. localhost에서 실제 타일과 출발·도착 마커 표시를 확인했다. 다른 환경에서는 해당 도메인의 키 설정을 다시 확인한다.

## 확인할 흐름

개발 서버에서 `/?preview=congestion#detail`로 환승 경로를, `/?preview=short#detail`로 단일 지하철 구간을, `/?preview=bike#detail`로 따릉이 경로를 확인할 수 있다. 초기화 옵션은 개발 모드에서만 동작하며 짧은 경로·따릉이는 실제 API 계약 fixture를 사용한다. 재고와 예측도 샘플로 확인하려면 각각 `VITE_BIKE_STOCK_MOCK=true`, `VITE_BIKE_PREDICTION_MOCK=true`를 개발 서버에 설정한다.

1. 홈에서 도착지를 검색하고 도곡역을 선택한다.
2. 대표 경로와 이어지는 다른 경로를 스크롤하며 선택한다. 우선순위를 변경하거나 이동수단을 필터링한다.
3. 바텀시트 손잡이는 클릭, 위아래 드래그, 키보드 위아래 화살표로 조작한다. Escape는 기본 높이로 돌린다.
4. 상세 화면에서 구간 안내를 확인하고 길안내를 시작한다.
5. 상단 미리보기 도구의 ‘다음 단계’, ‘탑승 확인’, ‘경로 제안’으로 시나리오를 확인한다. `VITE_GUIDANCE_MOCK=true`이거나 API 주소가 없으면 샘플 안내 응답을 사용하고, 실제 API 모드에서는 실시간 열차 도착과 잔여 경로 재탐색 endpoint를 호출한다.
6. 안내 중 뒤로 가기나 홈 이동 후 하단 안내 바를 눌러 같은 단계로 돌아온다. 다른 경로를 검색하거나 필터를 바꿔도 기존 안내가 유지되고, 새 안내로 바꾸려면 전환을 확인한다. 안내 종료·도착 후에는 복귀 바가 사라진다. 새로고침하면 검색 조건·후보·선택·안내 상태는 복원하지 않고 홈에서 시작한다.

## 구현 범위와 데이터

- React + TypeScript + Vite + TailwindCSS, Lucide 아이콘. 스타일은 디자인 토큰과 CSS 클래스로 관리한다.
- `src/components`: 바텀시트, 접근 가능한 네이티브 모달.
- `src/features/route`: 경로 타입, 정렬/필터/시간 계산, 경로 카드와 검색/선택 상태.
- `src/features/map`: 카카오 지도와 현재 위치 훅.
- `src/features/guidance`: 안내 상태와 관련 모달.
- `src/api/mock`: 샘플 데이터와 비동기 데이터 접근 구현.
- `src/pages`: 각 화면.
- `src/App.tsx`: 페이지·지도·모달 조립. `src/app`: 화면 이동과 기능 간 흐름.
- 지도와 일반 장소명·도로명 주소 검색은 카카오 JavaScript SDK를 사용한다. 장소 검색 결과에 좌표가 없는 항목은 화면에 표시하지 않는다. 실제 API 모드의 경로 입력은 백엔드 역 검색 결과를 사용하고, 선택한 역 ID로 경로를 요청한다.
- 샘플 경로와 시간은 역삼 → 도곡, 09:41 출발 기준으로 고정했다. 실제 API 모드에서는 경로 요청 시각과 서버 응답의 소요시간으로 도착 시각을 계산한다.
- GPS 현재 위치 조회는 홈 진입·재진입 또는 현재 위치 버튼 클릭 시 1회 연결하며, 길안내 화면에서는 위치 권한을 허용한 경우 `watchPosition`으로 자동 추적한다. 권한 거부·현재 위치 없음 상태에서는 수동 단계 안내를 사용할 수 있다.
- 지하철 구간의 탑승 확인은 현재 역·노선 ID로 실시간 열차 도착 정보를 조회하고, 경로 제안은 현재 단계 경계 이후의 잔여 경로를 다시 요청한다.
- 새로고침하면 검색 조건과 진행 상태가 초기화된다. 해시가 현재 검색·선택 상태와 맞지 않는 경우 앱이 안전한 화면으로 보정한다. 향후 API 계약 확정 시 데이터 계층을 교체한다.

구조와 작업 기준은 [문서 시작점](README.md)을 참고한다.
