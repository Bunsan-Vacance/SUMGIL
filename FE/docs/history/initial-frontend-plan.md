# Frontend

> 보존된 초기 기획이다. 현재 실행 방법과 구조는 [최신 문서](../README.md)를 참고한다.

**스택** React · TypeScript · TailwindCSS · Vite

> **숨길** — 지하철 탈출 내비게이션.
> "혼잡도 152%"를 "앉을 확률 8%"로 바꿔 보여주는 파트다.
> 숫자를 정확히 내려주는 것보다 **사용자가 3초 안에 판단하게 만드는 것**이 이 파트의 일이다.

---

## 1. UX 원칙

기획 전체를 관통하는 원칙 셋. 화면을 만들 때 여기서 어긋나면 다시 본다.

**① 명령하지 않는다, 선택지를 준다.**
앱은 "내리세요"라고 말하지 않는다. 두 카드를 나란히 보여주고 결정은 사용자가 한다. 버튼 문구도 "탈출하기"가 아니라 "따릉이 경로 보기"에 가깝다.

**② 전문 용어를 사용자 언어로 바꾼다.**
`혼잡도 152%` → **`앉을 확률 8%`**. 서버가 혼잡도를 같이 내려주더라도 화면의 주인공은 착석 지수다.

**③ 근거를 함께 보여준다.**
"13분"만 띄우지 않는다. "같은 구간을 실제로 탄 이용자 기록 기준"인지 "지도 추정치"인지 구분해 표시한다. 응답의 `source` 필드가 그 근거다.

## 2. 핵심 화면

### 2.1 목적지 입력 · 추적 시작

목적지를 넣으면 기준 경로(예: 선릉 환승, 23분)를 안내하고 추적을 시작한다.

> GPS로 현재 역을 자동 판별하는 것은 지하에서 신뢰하기 어렵다. **사용자가 현재 역을 직접 탭하는 방식**을 기본으로 두고, GPS는 보조로만 쓴다.

### 2.2 실시간 비교 카드 — 킬러 화면

현재 역 기준으로 두 선택지를 나란히 갱신한다.

```
┌──────────────────────────────┐  ┌──────────────────────────────┐
│ 🚇 계속 타고 가기      15분   │  │ 🚲 한티역에서 내리기    13분  │
│                              │  │                              │
│ 지금 앉을 확률 7%            │  │ 2번 출구 대여소              │
│ 3정거장 뒤 선릉에서 대량 하차 │  │ 잔여 6대                     │
│ → 이후 앉을 확률 55%         │  │ 도착 시점 예상 4대           │
│                              │  │ 실제 이용 기록 기준          │
└──────────────────────────────┘  └──────────────────────────────┘
```

- 시간 차이가 크지 않을 때 어느 쪽도 강조하지 않는다. 착석 지수와 잔여 대수가 판단 재료가 된다.
- `blockedReason`이 있으면(재고 부족·우천) 자전거 카드를 비활성화하고 **사유를 표시**한다. 조용히 숨기지 않는다.

### 2.3 빠름 ↔ 쾌적함 슬라이더

슬라이더를 옮기면 경로가 다시 뽑힌다. 값은 백엔드의 λ(혼잡 페널티 가중치)로 전달된다.

"7분 손해 보고 쾌적함을 산다"는 선택이 성립하려면 **바뀐 결과가 즉시 보여야 한다.** 조작 중에는 낙관적 UI로 반응하고 응답으로 확정한다.

### 2.4 따릉이 경로 안내

자전거 카드를 탭하면 지도에 `출구 → 대여소 → 목적지` 경로를 그린다. 대여소 잔여 대수를 지도 위에 함께 띄운다.

## 4. 초기화

**아직 프로젝트가 생성되지 않았다.** 폴더만 잡아둔 상태이며, 아래 명령으로 스캐폴딩한다.

```bash
cd FE

# Vite + React + TypeScript
npm create vite@latest . -- --template react-ts
npm install

# TailwindCSS v4
npm install tailwindcss @tailwindcss/vite
```

`vite.config.ts`에 플러그인을 등록한다.

```ts
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'
import tailwindcss from '@tailwindcss/vite'

export default defineConfig({
  plugins: [react(), tailwindcss()],
})
```

`src/index.css` 최상단에 한 줄을 추가한다.

```css
@import 'tailwindcss';
```

**추가로 검토할 라이브러리**

| 용도      | 후보                                   |
| --------- | -------------------------------------- |
| 지도      | Kakao Maps SDK (국내 좌표·주소 정확도) |
| 서버 상태 | TanStack Query (실시간 재고 폴링·캐시) |
| 라우팅    | React Router                           |
| 전역 상태 | Zustand (슬라이더 값, 추적 상태)       |

> 스캐폴딩 도구가 디렉터리 구조를 직접 만들기 때문에, 충돌을 피하려고 하위 폴더를 미리 만들어두지 않았다. 초기화 후 아래 구조를 얹는다.

## 5. 목표 디렉터리 구조

```
FE/
├─ public/
├─ src/
│  ├─ api/         API 클라이언트, 요청·응답 타입
│  ├─ assets/      이미지·폰트
│  ├─ components/  재사용 UI (버튼, 카드 셸, 슬라이더)
│  ├─ features/
│  │  ├─ escape/      비교 카드, 판정 표시
│  │  ├─ congestion/  착석 지수 시각화
│  │  ├─ bike/        대여소 재고, 자전거 경로
│  │  └─ route/       목적지 입력, 경로 추적
│  ├─ hooks/       공용 커스텀 훅
│  ├─ pages/       라우트 단위 화면
│  ├─ stores/      전역 상태
│  ├─ types/       공용 타입 정의
│  └─ utils/       순수 유틸 함수
├─ index.html
├─ vite.config.ts
└─ tsconfig.json
```

## 6. 실행

```bash
npm run dev      # 개발 서버 (http://localhost:5173)
npm run build    # 프로덕션 빌드
npm run preview  # 빌드 결과 미리보기
npm run lint     # 린트
```

## 7. 작업 규칙

- **API 주소는 하드코딩하지 않는다.** `.env`의 `VITE_API_BASE_URL`을 사용하고 `.env.example`에 키 이름만 남긴다.
- 컴포넌트는 `features/` 우선으로 배치하고, 두 곳 이상에서 쓰일 때 `components/`로 올린다.
- 타입은 `any`를 두지 않는다. 서버 응답 타입은 `api/`에 모아 **BE Swagger 명세와 1:1로 맞춘다.**
- **모바일 우선.** 지하철 안에서 한 손으로 쓰는 화면이다. 비교 카드는 세로 스크롤 없이 한 화면에 들어와야 한다.
- 실시간 값(잔여 대수, 도착 시간)은 **갱신 시각을 함께 표시**한다. 오래된 값을 최신인 척 보여주지 않는다.
