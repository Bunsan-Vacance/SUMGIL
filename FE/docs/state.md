# 상태 소유와 화면 흐름

## 상태를 두는 기준

한 화면·컴포넌트에서만 필요한 상태는 그곳에 둔다. 여러 화면에서 유지해야 하는 상태는 앱에서 기능 훅을 한 번 호출해 소유하고 props로 전달한다. 훅 파일을 분리했다고 각 페이지에서 같은 훅을 다시 호출하면 서로 다른 상태가 만들어지므로 주의한다.

| 상태                                          | 소유자                            | 수명 / 변경 규칙                                                                   |
| --------------------------------------------- | --------------------------------- | ---------------------------------------------------------------------------------- |
| 현재 화면                                     | `useNavigation`                   | 해시 변경과 브라우저 앞/뒤 이동을 반영                                             |
| 출발·도착, 이동수단, 우선순위, 후보·선택 경로 | `useTrip` + `tripReducer`         | 페이지 이동 동안 유지, 새로고침 시 빈 후보·선택 초기값                             |
| 경로 조회 상태·오류                           | `useTrip`                         | `idle/loading/success/error`; 대상 변경·새 검색 시 이전 요청 취소                  |
| 검색 대상(출발/도착), 현재 모달               | `useRoutePlanner`                 | 화면 이동 시 모달 닫기                                                             |
| 검색어                                        | `SearchPage`                      | 검색 화면을 나가면 초기화                                                          |
| 장소 조회 결과·로딩·오류                      | `usePlaceSearch`                  | 검색어 변경 시 이전 요청 취소                                                      |
| 최근 검색 장소                                | `SearchPage` + `localStorage`     | 선택한 유효 장소를 최대 10개 최신순으로 보관, 검색 화면에서 삭제 가능              |
| 필터 임시 선택                                | `FilterDialog`                    | 적용할 때만 trip에 반영, 닫으면 버림                                               |
| 안내 경로·출발/도착·단계·탑승 열차·완료 상태  | `useGuidance` + `guidanceReducer` | 시작 시 검색 상태에서 독립된 세션으로 보관. 화면 이동·새 검색·필터와 무관하게 유지 |
| 시트 높이·드래그                              | `useBottomSheet`                  | 해당 페이지가 마운트된 동안 유지                                                   |
| SDK 지도·마커 인스턴스                        | `useKakaoMap`의 ref               | 일반 화면 상태와 분리, 정리 시 마커 제거·observer 해제                             |
| 위치 요청 중                                  | `useCurrentLocation`              | 버튼 클릭으로만 시작, 화면/대상 변경 후 늦은 응답 무시                             |
| 토스트                                        | `useToast`                        | 2.8초 후 또는 화면 변경 시 제거                                                    |

## 핵심 흐름

1. 홈에서 출발·도착 검색을 연다.
2. 도착지를 선택하면 동일 출발지인지 검증한 뒤 경로를 요청하고 결과 화면으로 이동한다. 결과 화면에서 출발지·도착지를 바꾸거나 교환하면 진행 중 요청을 취소하고 새 출발·도착으로 경로를 다시 요청한다. 홈에서는 출발지 변경·교환한 값만 유지한다.
   결과 화면의 출발·도착 요약 칸을 누르면 각각 해당 검색 화면을 연다.
   검색 화면에서는 현재 위치 또는 지도에서 좌표를 선택할 수 있으며, 검색을 취소하면 검색에 진입하기 전 화면과 값을 유지한다.
3. 후보 목록은 화면 상태에 저장한다. 필터와 우선순위가 바뀌면 `getRoutes`로 표시 목록을 계산한다.
4. 필터에서 현재 선택 경로가 제외되면 첫 번째 사용 가능한 경로를 선택한다. 정렬 변경만으로는 사용자가 선택한 경로를 바꾸지 않는다.
5. 결과가 없으면 새 안내 시작 버튼을 표시하지 않는다. 성공한 빈 결과는 조건 변경, 조회 오류는 재시도로 복구한다. 이미 진행 중인 안내는 검색 결과 유무와 무관하게 돌아갈 수 있다.
6. 첫 안내 시작 시 경로와 출발·도착을 함께 보관하고 단계 0, 열차 미선택으로 시작한다. 같은 안내로 돌아갈 때는 단계와 탑승 열차를 유지한다. 다른 경로의 안내 시작은 전환 확인 후에만 기존 세션을 교체한다.
7. 뒤로 가기·홈 이동·검색·필터·후보 선택은 안내를 종료하지 않는다. 안내 화면 밖에서는 목적지·남은 시간·현재 구간을 담은 하단 바로 복귀한다. 검색 상태와 별도로 보관한 안내 경로를 사용하므로 지도·구간·도착지가 새 검색 값으로 바뀌지 않는다.
8. 명시적인 안내 종료는 세션을 지운다. 마지막 단계에서 완료로 표시하고 도착 화면으로 이동하며 복귀 바를 숨긴다. 종료 후 과거 안내 URL에 접근해도 세션을 다시 시작하지 않는다.
9. 제안 수락은 안내 세션의 경로만 바꾸고 단계를 초기화하며, 검색 중인 후보와 조건은 유지한다. 현재는 샘플 시나리오의 재시작이며 실제 잔여 경로 재탐색이 아니다.

## 저장하지 않는 값

표시 목록, 도착 시간, 남은 시간, 다음 구간은 원본 상태에서 계산한다. 별도 상태로 중복 보관하지 않아 선택 경로와 표시 정보가 어긋나는 일을 줄인다.

## 아직 미리보기인 부분

- 경로 응답은 도착지와 무관한 고정 샘플이다.
- 안내·도착 해시는 안내 세션을 먼저 확인한다. 진행 중인 세션은 안내로, 완료된 세션은 도착으로 보낸다. 세션이 없으면 현재 검색 상태에 따라 홈·결과·상세로 보정한다. 다른 화면도 검색 상태에 맞지 않으면 안전한 화면으로 보정하며 history replace를 사용한다.
- 브라우저 뒤로 가기는 화면 이동을 되돌리며, 경로·안내 상태는 현재 메모리 상태에 맞춰 다시 검증한다. 과거 상태 스냅샷을 복원하지 않는다.
- 최근 검색을 제외한 경로·안내 상태는 메모리에 있고 새로고침 후 복구하지 않는다.
- 경로 ID `fast`, `calm`은 샘플 대표 경로 분류에도 사용한다. 실제 서버 ID에 이 규칙을 강제하지 말고 API 연결 시 별도 분류 필드를 합의한다.
