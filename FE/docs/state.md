# 상태 소유와 화면 흐름

## 상태를 두는 기준

한 화면·컴포넌트에서만 필요한 상태는 그곳에 둔다. 여러 화면에서 유지해야 하는 상태는 앱에서 기능 훅을 한 번 호출해 소유하고 props로 전달한다. 훅 파일을 분리했다고 각 페이지에서 같은 훅을 다시 호출하면 서로 다른 상태가 만들어지므로 주의한다.

대여소 선택 카드의 거치대 수와 조회한 지도 중심 기준 거리는 nearby 응답에 있을 때만 표시한다.

상세와 길안내는 동일한 `DetailPage`와 `RouteTimeline`을 사용한다. 안내 시작 시 현재 구간 강조와 안내 상태만 추가하고 지도·바텀시트를 유지한다. 전체/구간 혼잡도와 따릉이 현재 재고·도착 예측을 유지한다. 단계가 바뀌면 시트 내부만 현재 구간으로 스크롤한다. 수동 이전/다음, 현재 구간 선택, 탑승 열차 선택과 재탐색은 접힌 '안내 조정' 안에 두고, 실제 이용 확인 버튼은 현재 구간에 바로 표시한다.

안내 화면의 위치 추적은 `useGuidance`에서 한 번만 생성하며 유효한 같은 위치를 지도와 도착 판정에 함께 사용한다. 위치 권한 거부·현재 위치 없음·오차가 큰 상태를 구분한다. 15초보다 오래된 위치, 중복 타임스탬프, 무효 좌표는 도착 판정에 사용하지 않는다. 위치 갱신이 15초 동안 없으면 현재 위치 마커와 도착 후보를 비운다.

도보·자전거는 오차 30m 이하이며 거리+오차가 도착점 40m 안에 서로 다른 위치 관측으로 연속 두 번 들어오면 자동 전환한다. 버스는 도착 반경 50m를 사용하며 먼저 도착 반경 밖의 위치를 관측해야 한다. 도착 좌표가 없으면 현재 leg의 geometry 마지막 좌표만 대체 사용하며, 둘 다 없으면 직접 구간을 조정하도록 알린다. 마지막 이동 구간도 같은 조건으로 도착 처리한다.

지하철은 GPS만으로 탑승·하차 처리하지 않는다. '탑승했어요'로 탑승 상태를 기록하고 '하차했어요'로 다음 이동 구간에 진입한다. 별도 BOARDING/ALIGHTING/BIKE_RENTAL/BIKE_RETURN 행동도 위치 근접만으로 완료하지 않고 직접 확인한다. 열차 선택 모달도 실제 탑승 확인임을 명시하며, 열차 정보 없이 확인할 수 있다. 지하 구간을 시간만으로 진행시키지 않는다. 수동 단계 변경·재탐색·위치 중단 시 연속 관측을 초기화하며, 실제 위치와 확인 후보는 저장/복원하지 않는다.

지도는 유효한 위치를 따라가되 사용자가 드래그하면 추종을 멈추고, 현재 위치 버튼으로 재개한다. 안내 화면을 나가면 위치 추적은 중단하며 복귀할 때 새 관측부터 시작한다. 이 기능은 구간 도착 판정과 현재 위치 표시이며, 경로 이탈 자동 재탐색·회전별 안내·이동량 기반 남은 시간/ETA 갱신은 포함하지 않는다. 실제 휴대폰 이동 및 지하철 구간의 현장 검증은 별도로 필요하다.

## 핵심 흐름

0. 앱 최초 진입 시 아이콘과 캐치프레이즈를 1.25초 표시한 뒤 현재 해시로 요청된 화면을 렌더링한다. 시작 화면은 앱 마운트마다 한 번만 나타나며 화면 이동 때 다시 표시하지 않는다.

1. 홈에서 출발·도착 검색을 열거나 장소 탐색으로 이동한다. 장소 탐색은 검색 결과와 지도 마커를 함께 보여 주며, 선택한 장소는 카드의 출발지·도착지 설정 버튼을 눌렀을 때만 trip에 반영한다. 홈 패널의 집·회사·즐겨찾기 칩은 등록된 장소로 바로 경로를 찾고, 미등록 집·회사 칩은 검색 화면을 등록 모드로 열어 선택한 장소를 저장한 뒤 이전 화면으로 돌아온다. 검색 화면의 별 토글로 즐겨찾기를 추가·해제한다.
2. 도착지를 선택하면 동일 출발지인지 검증한 뒤 경로를 요청하고 결과 화면으로 이동한다. 결과 화면에서 출발지·도착지를 바꾸거나 교환하면 진행 중 요청을 취소하고 새 출발·도착으로 경로를 다시 요청한다. 홈에서는 출발지 변경·교환한 값만 유지한다.
   결과 화면의 출발·도착 요약 칸을 누르면 각각 해당 검색 화면을 연다. 목적지가 이미 있으면 홈·장소 탐색에서 이어진 출발지 검색도 결과를 다시 조회한다.
   검색 화면에서는 현재 위치 또는 지도에서 좌표를 선택할 수 있으며, 검색을 취소하면 검색에 진입하기 전 화면과 값을 유지한다.
   출발 시간은 시·분 휠에서 적용하면 오늘(Asia/Seoul) 기준으로 재조회한다. 선택한 시간은 이동수단 변경·장소 수정·교환·재시도에도 유지하며, 새로고침하면 초기화한다.
   결과 화면은 지도 없이 화면 너비를 채운 경로 목록을 세로로 스크롤한다. 경로 영역 어디를 눌러도 해당 경로를 선택한 뒤 상세 화면으로 이동한다. 목록의 구간은 출발 지점·노선명과 마지막 도착 지점만 표시하고, 전체 구간 안내는 상세 화면에서 확인한다.
   검색이 성공하면 자전거 경로를 포함한 후보를 즉시 표시한다. 추천 경로는 소요 시간과 유효한 `congestionPrediction`을 기준으로 계산하며, 결과 화면에서 따릉이 재고·도착 예측을 기다리거나 후보를 제외하지 않는다.
3. 후보 목록은 화면 상태에 저장한다. 검색 시각과 현재 priority를 요청에 함께 보내고, API 응답 후보는 서버가 만든 순서를 시작점으로 사용한다. TIME은 시간순, COMFORT는 유효한 `congestionPrediction`만 혼잡도순으로 정렬하고 예측값이 없는 후보는 뒤에 둔다. 우선순위 변경은 직전 검색의 출발 시각을 유지해 TIME/COMFORT로 재조회한다. 목적지가 있고 이미 검색된 상태에서 필터를 적용하거나 전체 수단을 복원하면 WALK를 포함한 modes로 경로를 다시 요청한다. 목적지가 없거나 아직 `idle`이면 필터 상태만 바꾸고 검색하지 않으며, 재요청 시 이전 요청을 취소하고 늦은 응답을 무시한다.
4. 필터에서 현재 선택 경로가 제외되면 첫 번째 사용 가능한 경로를 선택한다. 우선순위 재조회 중에는 이전 후보와 선택을 비우고, 성공하면 새 응답의 첫 경로를 선택한다.
5. 결과가 없으면 새 안내 시작 버튼을 표시하지 않는다. 성공한 빈 결과는 조건 변경, 조회 오류는 재시도로 복구한다. 이미 진행 중인 안내는 검색 결과 유무와 무관하게 돌아갈 수 있다.
6. 첫 안내 시작 시 경로와 출발·도착을 함께 보관하고 단계 0, 열차 미선택으로 시작한다. 상세와 같은 지도·시트에서 안내 모드로 전환하며 시트 높이를 유지한다. 같은 안내로 돌아갈 때는 단계와 탑승 열차를 유지한다. 다른 경로의 안내 시작은 전환 확인 후에만 기존 세션을 교체한다.
7. 뒤로 가기·홈 이동·검색·필터·후보 선택은 안내를 종료하지 않는다. 안내 화면 밖에서는 목적지·남은 시간·현재 구간을 담은 하단 바로 복귀한다. 검색 상태와 별도로 보관한 안내 경로를 사용하므로 지도·구간·도착지가 새 검색 값으로 바뀌지 않는다.
8. 명시적인 안내 종료는 세션을 지운다. 마지막 단계에서 완료로 표시하고 도착 화면으로 이동하며 복귀 바를 숨긴다. 종료 후 과거 안내 URL에 접근해도 세션을 다시 시작하지 않는다.
9. 제안 수락은 안내 세션의 경로만 바꾸고 단계를 초기화하며, 검색 중인 후보와 조건은 유지한다. 실제 API 모드에서는 현재 단계의 경계 ID와 목적지, 이동 조건으로 잔여 경로를 재탐색한다.

## 저장하지 않는 값

표시 목록, 도착 시간, 남은 시간, 다음 구간은 원본 상태에서 계산한다. 별도 상태로 중복 보관하지 않아 선택 경로와 표시 정보가 어긋나는 일을 줄인다.

## 아직 미리보기인 부분

- `VITE_API_BASE_URL`이 없을 때의 경로 응답만 도착지와 무관한 고정 샘플이다. 환경 변수가 있으면 경로 repository가 백엔드 응답을 사용하지만, 좌표 API 계약이나 실서버 길찾기 검증이 완료됐다는 뜻은 아니다.
- 안내·도착 해시는 안내 세션을 먼저 확인한다. 진행 중인 세션은 안내로, 완료된 세션은 도착으로 보낸다. 세션이 없으면 현재 검색 상태에 따라 홈·결과·상세로 보정한다. 다른 화면도 검색 상태에 맞지 않으면 안전한 화면으로 보정하며 history replace를 사용한다.
- 브라우저 뒤로 가기는 화면 이동을 되돌리며, 경로·안내 상태는 현재 메모리 상태에 맞춰 다시 검증한다. 과거 상태 스냅샷을 복원하지 않는다.
- 검색 결과는 메모리에 두며, 안내 세션은 `sessionStorage`로 같은 탭에서 복원한다. 위치 좌표·위치 상태·연속 위치 확인 후보는 저장/복원하지 않고 새로 관측한다.
- 경로 ID `fast`, `calm`은 샘플 대표 경로 분류에도 사용한다. 실제 서버 ID에 이 규칙을 강제하지 말고 API 연결 시 별도 분류 필드를 합의한다.
